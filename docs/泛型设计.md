# 泛型设计（完整第一版）

> 状态：已实现。泛型覆盖类、函数、方法、接口、枚举，统一走编译期单态化，不做类型擦除；
> `std` 提供 `Vec<T>`、`Map<K: Eq, V>`、`Set<T: Eq>` 与 `Algorithms`，不提供 `Any` 装箱容器。

## 1. 总原则

- 不做 `Any` 装箱、不做运行时类型擦除；
- 所有类型参数在编译期替换为具体类型；
- 每个具体实例生成独立的 class / function / method / interface 实例；
- 模板本身不进入 codegen；`.mylib` API 导出泛型模板的完整源码（含函数/方法体），消费端据此实例化；
- 支持接口 bound（`T: Show`），不做高阶类型和 `where` 子句。

## 2. 语法

### 2.1 泛型类

```myl
class Vec<T> {
    T[] data;
    i32 count;

    pub fn init() -> void { this.data = new T[4]; this.count = 0; }
    pub fn push(T value) -> void { /* ... */ }
    pub fn get(i32 index) -> Option<T> { /* ... */ }
}
```

使用：

```myl
Vec<i64> ints = new Vec<i64>();
Vec<string> names = new Vec<string>();
```

### 2.2 泛型函数

```myl
fn identity<T>(T value) -> T {
    return value;
}

fn main() -> i32 {
    i64 a = identity(42);      // 由期望类型 i64 推断 T=i64
    string s = identity("hi"); // 由参数字面量推断 T=string
    return 0;
}
```

类型实参可以显式写 `<...>`，也可以省略。省略时按以下顺序推断：

1. 先看调用点的期望类型（赋值目标、函数参数、`return` 等）；
2. 再用实参提示绑定类型参数：字面量直接给出类型；变量、字段访问等表达式取 sema 求出的实际类型；
3. 仍无法绑定的参数会报 `无法推断...的类型实参`，此时需要显式写 `<...>`。

第一版推断不是完整的 Hindley-Milner 统一：复杂嵌套泛型、链式调用仍可能需要显式类型实参。

泛型模板体内的接收者方法调用按模板签名检查，例如 `fn first<T>(Vec<T> v) -> T { return v.get(0); }`；外层实例化后会用具体接收者重新检查并绑定具体方法。

### 2.3 泛型方法

```myl
class Box<T> {
    T value;

    pub fn init(T v) -> void { this.value = v; }

    pub fn Map<U>(U f(T)) -> Box<U> {
        return new Box<U>(f(this.value));
    }
}
```

调用：

```myl
Box<i64> b = new Box<i64>(1);
Box<string> s = b.Map<string>(to_string);
```

泛型方法的实例键是 `(所属 class 实例, 方法模板, 方法类型实参)`。
普通方法也可以出现在泛型类里，随 class 实例一起单态化。

### 2.4 泛型接口

```myl
interface Container<T> {
    fn get(i32 index) -> T;
    fn len() -> i32;
}

class Vec<T> {
    // ...
    pub fn get(i32 index) -> T { /* ... */ }
    pub fn len() -> i32 { /* ... */ }
}

Container<i64> c = new Vec<i64>();
```

泛型接口按具体实例生成 vtable：

- `Container<i64>` 和 `Container<string>` 是两个不同的接口实例；
- class 实现检查在实例化后的签名上进行；
- 动态派发使用具体实例的 vtable，不做运行时类型擦除。

### 2.5 泛型枚举

```myl
enum Maybe<T> {
    Nothing,
    Just(T),
}

Maybe<i64> m = Maybe::Just(7); // 由左侧具体枚举类型推断 T=i64
```

枚举和 class 共用同一套单态化机制；变体构造使用 `Maybe<i64>::Just(7)`，
`match` 可以用 `Maybe::Just(x)` 让 sema 按匹配对象的具体实例推断枚举。

### 2.6 类型参数 bound

```myl
interface Show {
    fn show() -> string;
}

fn pick<T: Show>(T value) -> T {
    return value;
}
```

- 语法是 `T: Interface`，多个 bound 用 `+` 连接；
- bound 只能是 interface；
- 模板体内 `T` 按 bound 接口视图检查，可以直接调用 bound 声明的方法；
- 实例化时再按已有接口兼容规则检查：class/enum 必须具备接口要求的同名方法且签名一致；
- 数值 / `bool` / `string` 对 `ToString` bound 内建放行；
- 不满足 bound 在实例化点报 `MYL102`，不会进入后端。

### 2.7 Eq / Ord：不带 vtable 的 bound 协议

`Eq` / `Ord` 用普通 interface 声明，但方法参数里使用 `Self`：

```myl
pub interface Eq {
    fn equals(Self other) -> bool;
}

pub interface Ord {
    fn compare(Self other) -> i32;
}
```

class / enum 只要提供签名兼容的方法就满足接口：

```myl
class Good {
    pub i64 v;
    pub fn equals(Good other) -> bool { return this.v == other.v; }
    pub fn compare(Good other) -> i32 {
        if (this.v < other.v) { return -1; }
        if (this.v > other.v) { return 1; }
        return 0;
    }
}
```

内置 `i8`…`u64`、`f32` / `f64`、`bool`、`string` 由编译器提供比较实现，不需要在 core 里为每个类型写一遍方法。

约束：

- `Self` 只能出现在 interface 方法签名中；其他位置的 `Self` 报 `MYL102`；
- `Eq` / `Ord` 是 **bound-only interface**：不生成运行期 interface 值、vtable 或 `Self` 相关的 C 结构；只能用于 `T: Eq` / `T: Ord`；
- `equals` / `compare` 可以在泛型模板体中使用，例如 `values.get(i).equals(value)`；
- `Ord` 约定返回负数 / 0 / 正数；`bool` 按 `false < true`，浮点 `NaN` 不参与全序（当前未定义专门语义）；
- 不实现 blanket impl、coherence 或自动派生；class / enum 必须显式写方法。

基于它的标准库函数：

```myl
pub fn contains<T: Eq>(Vec<T> values, T value) -> bool;
pub fn index_of<T: Eq>(Vec<T> values, T value) -> i64;
pub fn sort<T: Ord>(Vec<T> values) -> void;
pub fn extend<T>(Vec<T> values, Vec<T> other) -> void;
pub fn min<T: Ord>(T a, T b) -> T;
pub fn max<T: Ord>(T a, T b) -> T;
```

`contains` / `index_of` / `sort` / `extend` 在 `std/src/Algorithms.myl`，`min` / `max` 在 `core/Compare.myl`。它们是自由函数，不是 `Vec<T>` 方法；方法级 bound 尚未实现。`std` 同时提供 `Map<K: Eq, V>` 与 `Set<T: Eq>`，第一版均为线性查找，不做哈希。

## 3. 类型表示与延迟单态化

泛型类型在类型检查阶段不再绑定到某个具体 `Decl`，而是保留规范化的类型结构：

```rust
Type::Adt { base: DeclId, args: Vec<Type> }
Type::Param(String)
```

- `base` 是 class / enum / interface 模板的声明 id；
- `args` 是规范化后的类型实参，可以继续嵌套 `Adt`、`Option`、`Result`、数组等；
- `Vec<i64>` 与 `Vec<string>` 是同一个 `base` 的不同 `args`，不创建两个具体类型声明；
- 模板方法体里的 `T` 是 `Type::Param("T")`，`this` 是 `Type::Adt { base: 当前模板, args: [Param("T")] }`；
- 泛型调用先记录为 `Res::AdtCtor` / `Res::AdtFn` / `Res::AdtMethod` / `Res::AdtStaticMethod` / `Res::AdtField` / `Res::AdtVariant`，只检查签名，不生成实例；
- `Type::Generic` / `Type::Named` 只出现在解析前的 AST 或少量尚未规范化的表达式里，进入后端前会被 `mono_type` 收敛。

### 3.1 mono 阶段

`monomorphize(prog, diags)` 在全部模板体检查完之后、模板被中和之前运行：

1. 扫描声明签名、字段、枚举变体、局部变量、表达式类型、`new` / 调用类型实参、`Res::Adt*`；
2. 递归物化类型实参：先处理 `Adt<Adt<...>>` 的内层，再处理外层；
3. 对每个 `(模板 id, 具体实参列表)` 查 `Program::generic_instances`，没有才复用旧的 `instantiate_class/enum/interface/fn/method` 生成具体声明；
4. 类型实参仍含 `Param` / `Infer` 的模板体内占位不生成后端类型；
5. 把 `Type::Adt` 改写为具体 `Type::Class` / `Type::Enum` / `Type::Iface`；
6. 把 `Res::Adt*` 改写为具体 `Res::Ctor` / `Res::Fn` / `Res::Method` / `Res::StaticMethod` / `Res::Field` / `Res::Variant`；
7. 对 `T: Eq` / `T: Ord` 的 bound 调用，在实参变为内置标量后改写为 `Builtin::ValueEq` / `Builtin::ValueCmp`；实参为具体 class/enum 时优先落到具体方法，接口接收者才保留 vtable 分派；
8. 重建 `Program::insts` / `Program::arrays`，确保 AST / MIR / LLVM 后端看到的都是具体类型。

这一步是“晚单态化”：模板函数/方法体只检查一次，实例体通过 `generics::subst_decl` 替换类型参数；类型检查阶段不因为 `Set<T>` 的新返回值而创建 `Set__i64`。`.mylib` 消费端仍然从导出的模板源码重新实例化，因此实例名必须由 `(模板名, 类型实参)` 稳定生成。

## 4. 名称与符号

- 具体实例名使用类型实参稳定后缀，例如 `Vec__i64`、`Box__i64`、`identity__i64`；
- 后端符号名基于该稳定实例名生成，消费端按相同规则实例化后可直接链接；
- `.mylib` API 导出泛型模板源码（含实现体）及原模块的 `import`，消费端从模板源码实例化；库自身已产生的具体实例仍在 MIR 段，具体实例名不进入 API；
- `.mylib` API 签名遇到已单态化的类型（如 `Class(Vec__i64)`）必须还原成 `Vec<i64>`，不能把后端实例名 `Vec__i64` 直接写进 API；
- 归档 MIR 带本包声明，以及本包实际引用到的外部具体实例闭包（如 std `Map<string, i64>`），不会复制整个 std；`--- refs` 记录 `decl_id -> 限定名`，链接时按名复用消费端已有实例或追加缺失实例，不能按 id 平移；
- 同一个包里的兄弟模块可能既被单独打成 `.mylib`，又作为依赖归档的 `依赖::模块` 子 API 段出现。driver 必须按 API 源码去重，只加载一次，并把 `Wrap.myl` / `Wrap` 这类源码 import 别名指向同一个虚拟模块；否则同一泛型模板会有两份 decl，实例化出两个同名具体类，三层嵌套返回值会串到错误实例。

## 5. 约束

第一版允许的实参：

- 数值 / `bool` / `string` / class / enum / 数组 / `Option` / `Result`；
- 不允许接口类型作为数组元素，也不允许 `Vec<Any>`；
- 支持接口 bound；模板定义处按 bound 检查方法调用，实例化点再检查实际实参；
- 类型实参可显式给出，也可按期望类型 + 实参实际类型推断；
- `Eq` / `Ord` 是 bound-only interface，不生成运行期 vtable；内置标量、`bool`、`string` 有内建比较实现；
- 不做隐式转换、不做一般化的约束求解。

## 非目标（冻结）

以下内容明确不是当前泛型机制的目标，不因“Go/Rust 有”而跟进；需要重新评审后才考虑：

- **不做类型集合/联合约束**：不支持 `~int`、`~string`、`comparable`、`~int | ~float64` 这类底层类型近似或联合约束；`T: Interface` 只接受接口 bound。
- **不做高级约束语法**：不支持 `where` 子句、关联类型、默认类型参数、高阶类型、泛型类型别名。
- **不做完整类型推断**：只保留调用点的局部定向推断（期望类型 + 实参实际类型）；不生成约束图、不做统一求解、不回溯。无法绑定的类型参数必须显式写 `<...>`，不自动猜。
- **不做 blanket impl**：接口是结构化鸭子类型，没有 `impl` 关键字，也没有“对所有 `T: A` 自动让 `T: B`”的实现模板、coherence 或冲突求解。需要适配时使用显式泛型辅助函数或包装类。
- **不做泛型 ABI**：不做 dictionary、GC shape stenciling 或预实例化泛型 ABI；`.mylib` 只做泛型模板源码 + import 导出，消费端重新实例化。
- **不做 `Any` 装箱**：不允许通过 `Any`/类型擦除把异构类型塞进同一个容器；`Vec<T>` 仍是单态化容器。
- **不做用户级特化**：单态化是内部实现方式，不提供特化声明、特化优先级或运行时类型信息。

这些边界的目的是保持泛型机制可预测、可解释，并避免引入约束求解和实现选择系统。

## 6. 实施顺序

1. **parser/AST**：`<T>` 声明、`<i64>` 类型应用、`new Vec<i64>`、函数/方法调用类型实参；
2. **单态化核心**：泛型 class + 泛型函数；
3. **泛型方法**：接收者实例 + 方法实参；
4. **泛型接口**：实例化 vtable 与实现检查；
5. **std/Vec<T>**：作为第一个真实消费者；
6. **三后端对拍 + 负例**。

## 7. 测试

- `Vec<i64>` / `Vec<string>` / `Vec<Box>` / `Vec<Vec<i64>>`
- `identity<i64>` / `identity<string>`
- `Box<i64>::Map<string>`
- `Container<i64>` 与 `Container<string>` 两个 vtable
- 负例：实参数量不符、`Vec<Any>`、未闭合 `>`、把 `Vec<i64>` 赋给 `Vec<string>`
- 推断失败负例：`empty<T>()` 在没有期望类型、没有实参时调用 `empty()` 报 `MYL102`，必须写成 `empty<i64>()`
- `EqOrd`：`contains` / `index_of`、`min` / `max`，覆盖 `i64`、`string`、自定义 class、`bool`、`f64`
- 负例：`M036_eq_bound` 缺少 `equals` 的 class 使用 `contains<T: Eq>` 报 `MYL102`
- 负例：`M037_self_scope` 在普通方法签名中使用 `Self` 报 `MYL102`
- `eq_mylib`：`has<T: Eq>` 通过 `.mylib` 导出后，消费端在 MIR / LLVM 都能实例化；bound 的 `Eq` import 会随 API 传播
- `generic_mylib`：`Vec<T>`、`Option<Vec<T>>`、`Vec<Vec<T>>`、泛型接口、泛型枚举跨 `.mylib` 链接；外部 std 类型/方法按 `--- refs` 限定名重映射
- `generic_closure`：多个归档各自闭包带入同一批 `Vec` / `Map` 具体实例时，消费端实例只复用不重建，避免 `Res::Method` id 悬空；同时覆盖泛型类字段 `Vec<T>` / `Map<string, Vec<T>>`、`Option<Vec<Vec<T>>>` 返回、泛型接口和泛型枚举的内部调用
- `multinest`：兄弟模块 `Wrap` 既单独归档、又作为 `Multi` 归档的子 API 出现时，三层与五层 `Vec<Vec<Vec<Vec<Vec<T>>>>>`、`Map<string, Vec<Vec<T>>>`、`Vec<Wrap<Wrap<i64>>>` 都必须返回正确最内层值；泛型静态方法 `Wrap<i64>::Make`、`Wrap<Wrap<Wrap<i64>>>::Make` 在 MIR 与 LLVM 生成阶段都必须按 MIR `Res` 的声明 id 找到实例化后的函数，不能按源码模板名 `Wrap::Make` 直接查符号
- MIR-C / LLVM / AST 输出一致
