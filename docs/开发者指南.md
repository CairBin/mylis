# Mylis 开发者指南

本指南面向修改 `mylc`、扩展语言、增加后端、替换运行时或对接新工具链的开发者。语言语义见 [`Mylis语言规范.md`](Mylis语言规范.md)，对外用法见 [`使用手册.md`](使用手册.md)。

---

## 1. 项目边界与长期约定

Mylis 的几个硬约束，扩展时应优先遵守：

1. **语言层不使用泛型/模板**。容器通过接口、装箱/拆箱和显式转换实现，不引入单态化。
2. **不内置 `Vec` / `Map` 等容器**。标准库按需提供，不把容器语义写进编译器。
3. **GC 可替换**。语言代码只依赖 `myrt/mylrt.h`，不直接调用 Boehm / mylgc 内部 API。
4. **默认 LLVM 后端，默认自研 GC**。C 后端保留为兼容基线，不能因为 LLVM 改动而退化。
5. **编译器 `mylc` 保持 Rust 零第三方依赖**（`cargo` 依赖仅标准库；语言服务器共用同一前端）。
6. **后端不静默回退**。某个结构未 lowering 时应明确报错，不应悄悄改用 C 后端。
7. **C 基线测试显式指定 `--backend mir`**。默认后端改成 LLVM 后，C 基线脚本必须保持 `--backend mir`，避免测试语义漂移。

## 2. 代码地图

```text
mylis/
├── mylc/src/
│   ├── lexer.rs          # 词法
│   ├── parser.rs         # 语法 → AST
│   ├── ast.rs            # AST / 类型 / 声明
│   ├── program.rs        # 模块装载、模块搜索根、import
│   ├── sema.rs           # 语义检查、类型检查、诊断
│   ├── mir.rs            # AST → MIR，MIR 数据结构与文本 dump
│   ├── mir/pass.rs       # MIR 辅助 pass / verify
│   ├── backend/
│   │   ├── mod.rs        # Backend trait / Artifact / ExportMode
│   │   ├── c.rs          # AST → C11
│   │   ├── mir_c.rs      # MIR → C11
│   │   ├── llvm.rs       # MIR → 文本 LLVM IR（默认）
│   │   └── ir.rs         # MIR 文本后端
│   ├── codegen/          # C 后端实现细节
│   ├── driver.rs         # 产物模式、工具链调用、链接、工程构建
│   ├── cli.rs            # 命令行解析
│   ├── manifest.rs       # mylis.toml + 包依赖图解析（路径/registry、菱形去重/冲突）
│   ├── semver.rs         # SemVer 解析与 `* / ^ / ~ / =` 约束
│   ├── lockfile.rs       # mylis.lock（路径依赖图 + 包校验和）
│   ├── sha256.rs         # 无第三方依赖的 SHA-256
│   ├── mylib.rs          # .mylib 归档：API 声明、MIR 合并、类型/函数 id 对齐
│   ├── mir_json.rs       # MirProgram JSON 编解码
│   ├── toolchain.rs      # C 工具链家族/规格发现
│   ├── diag.rs           # 诊断
│   ├── lsp.rs            # myls 语言服务器
│   └── main.rs           # mylc / myls 入口
├── mylrt-rs/             # Rust 运行时（C ABI 外壳 + Runtime/Gc/Platform trait）
├── mylgc/                # 自研 GC（Rust no_std staticlib）
├── myrt/                 # C ABI 头文件；mylrt.c 为参考实现
├── core/                 # 语言 core 层（编译器隐式提供）
├── std/                  # 独立 std 包（通过依赖/-I 显式引入）
├── toolchains/           # 工具链规格（*.toml）
├── tests/                # C 基线、对拍、LLVM、库模式、运行时验收
└── docs/
```

### 标准库命名约定

- 类名、静态方法：大驼峰，例如 `Io::PrintlnI32`、`Fmt::I64`、`Str::Concat`；
- 非类内函数：小写 + 下划线，例如 `fmt_i64`、`println_i32`、`sqrt64`；
- 类内实例方法、接口方法：小驼峰，例如 `toString`、`equals`；
- 变量（局部变量、成员变量、静态变量）：小驼峰，例如 `value`、`isEmpty`；
- 编译期常量：全大写 + 下划线，例如 `LEFT`、`PI`。
- `core` 层只依赖 C 标准库头和 `mylrt` ABI；`std` 是独立包，应用在 `mylis.toml` 中显式依赖。

### 依赖解析约定

- `manifest::build_graph` 不读锁，适合生成锁；`build_graph_with_pins` 用于正常构建，锁存在时强制按 pin 的版本/源解析。
- registry 依赖由 `manifest::resolve_registry` 解析：默认 `~/.mylis/registry`，命名 registry 用 `MYLIS_REGISTRY_<NAME>`；版本选择走 `semver::Req`。
- Git 依赖由 `manifest::resolve_git` 解析：裸仓库缓存 `~/.mylis/git/db/<url-hash>`，checkout 到 `~/.mylis/git/checkouts/<url-hash>/<commit>`；锁文件 source 为 `git+URL#commit`。
- `.mylib` 依赖由 `manifest::resolve_mylib` 解析：远程 URL 用 `curl` 下载到 `~/.mylis/mylib/downloads/<url-hash>.mylib`，本地路径相对依赖清单目录解析；`mylib::read` 校验内部 checksum，锁文件 checksum 是归档文件 SHA-256。包图里用合成 `Manifest` 表示它，`api_paths` 为每个模块记录虚拟路径；虚拟路径固定挂在**消费方项目根** `.mylib/<包名>/lib.myl`、`.mylib/<包名>/<模块路径>.myl`；嵌套模块 `vector::A` 对应 `.mylib/<包名>/vector/A.myl`，不要用归档所在目录，否则包图预加载和 driver 注入会生成两份同名 API，导致同一 class 有两个 decl id、C 后端出现未定义的 `struct C_n`。MIR 由 driver 用 `mylib::merge_into` 链接。
- `mylib::emit` 按根包模块生成多个 `--- api <段名>` 段：根包根 API 为 `lib`，子模块为 `<根包名>::vector`、`<根包名>::vector::A`；依赖包不写入 API/MIR，只在 `--- deps` 记录 `name|version|source|checksum`。driver 递归解析 `mylib+...` 依赖，依赖先于根包注入 API、合并 MIR。`mylib::read` 兼容旧的单 `--- api` 归档；新归档额外写 `--- refs`（外部函数/类型 id 到限定名），并按闭包带入本包实际引用到的外部具体实例（不复制整个 std）；`merge_into` 先按名复用已有声明，再追加缺失声明，`base + id` 仅作兜底；driver 只删除本归档 API 导出的 dummy 函数，外部闭包实例（如 std `Vec::len`）保留消费端已有 id，避免其它方法的 `Res::Method` 悬空。
- 原生载荷：`Mylib` 的 `native_static` / `native_shared` 是 `(文件名, 字节)`；归档使用 `--- native-static` / `--- native-shared` 段，内容为 Base64。带 native 载荷时从构建清单写入 `native_target` / `native_abi`，并与载荷一起参与 checksum；driver 读取后按当前 `mylis-build.json` 校验，不匹配直接拒绝。`Mylib::has_native()` 为真时 driver 跳过 `merge_into`，提取到 `~/.mylis/mylib/native/<archive-path-hash>/` 并加入链接参数。
- 原生载荷按 API 顶层函数名解析符号；C 后端在源码 include 后插入 `extern` 原型。LLVM 后端通过 `LlvmBackend.native_externs` 收集 `.mylib` API 顶层函数，在 IR 中生成 `declare`，调用目标解析为原生 C ABI 符号（优先 `@export` 名），而不是 Mylis mangled 符号。静态库输出用 `cc -r --whole-archive` 合并，动态库输出用 `-rpath` 保证运行期找到库。
- `publ` 的类型范围限定当前包、当前模块；函数范围限定当前模块。跨包或跨模块类型通过 `fmt_type` 输出 `pkg::Type` / `pkg::module::Type`，避免同名类型冲突。
- 导入 AST 与模块元数据：`ImportAst` 的 `names` / `selective` 保存 `import { A, B } from "..."`；`ModuleInfo` 有 `import_selected`（重复检查用）、`imported`（本模块裸名 → 模块 id）、`reexports`（`pub import { ... }` 名字 → 模块 id）。`program::load_module` 在同一文件内对 `import_selected` 做 `MYL011` 重复检查，并检查选择性导入名与本地 `decls[].name` 冲突；检查本地冲突必须直接遍历 `decls`，此时 `fn_syms` / `type_syms` 尚未构建。
- 查找规则（sema）：裸函数名 = 当前模块本地声明 → `imported` 选择性导入；裸类型名同理；限定名 `A::name` 先按 class/enum 静态成员解析，失败后回退到可见模块集合里的包函数 `A::name`。多段 `A::sub::name` 由 parser 在 `Tok::Ident` 分支循环消费 `::`，最终 `class = "A::sub"`，查找按完整模块名匹配。
- 再导出穿透：`pub import { X } from "A"` 同时写入 `imported` 和 `reexports`；`sema::find_exported_fn` / `find_exported_type` 先查目标模块本地声明，再沿 `reexports` 递归，使用 `HashSet<usize>` 防循环。这样上层 `import { X } from "B"` 能拿到 B 再导出的 A 符号。
- 模块可见性与名字再导出分开：`ModuleInfo.import_raw` 保存 `(path, line, col, is_pub, selective)`；`Sema::compute_visible` 只有 `is_pub && !selective` 时才把目标模块加入上层可见集。`pub import { X } from "A"` 只允许通过 `reexports` 拿到 X，不允许上层写 `A::other()`；要让 A 模块整体对上层可见，必须写 `pub import "A";`。
- 限定包函数调用在 `ExprKind::StaticPath` 分支回退：如果 `A` 不是 class/enum，但 `lookup_fn("A::name")` 命中，按普通函数调用检查 pub/unsafe/参数，写入 `Res::Fn(fid)`，并**显式设置 `e.ty`**（早期直接 `return ret` 会绕过 `check_expr` 尾部赋值，导致 MIR 把返回类型当 `Infer`、C 后端退化成 `myrt_i32`）。
- 用户模块只在 `visible` 模块里查找，必须显式 `import "dep/Foo"`；只有编译器生成的 `.mylib` API 模块允许扫描全部已加载模块，保证跨包签名自洽。`.mylib` 生成的 API 模块内部仍按上述选择性导入/再导出规则读取。
- API 类型 key 必须和 `mir::qualified_type_name` 一致：模块 stem 与类型名相同时为 `pkg::Type`，否则为 `pkg::module::Type`；方法 key 用 owner 类型 key 拼方法名。忽略这条会导致 `api_types` 映射到错误 decl id。
- `.mylib` 包名导入除了 `import "dep"` 根 API，也支持 `import "dep/Foo"`；`program::resolve_package_import` 在图中找不到 `dep` 独立 package 时，按 `dep::Foo` API 段标签回查。
- 新增依赖源类型时，要同时更新 `Dependency`、`build_graph_with_pins`、`LockPin`/`lockfile::read_pins`，并保证 `--update-lock` 能重写。
- 锁文件 checksum 在加载依赖后由 `lockfile::package_checksum` 重算并与 pin 比对；修改 path/registry 依赖内容后必须 `--update-lock`。

### 编译管线

```text
源文件
  → lexer
  → parser / AST
  → program（模块装载，import 解析）
  → sema（符号/类型检查）
  → mir::lower（AST → MIR CFG + SSA 值 + 局部槽）
  → backend
      ├── llvm   → 文本 LLVM IR → clang
      ├── mir_c  → C11 源码 → cc
      ├── c      → AST → C11 源码 → cc
      └── ir     → MIR 文本
  → driver：写临时产物、调用外部工具链、链接运行时/GC/用户库
```

关键点：

- `sema` 通过后，`mir::lower` 仍然可能产生错误；LLVM 后端还有自己的 precheck。
- `backend::Backend` 只接收 `ast::Program`；MIR 由各后端自行调用 `mir::lower`。
- `driver` 根据 `Args.backend` / `Args.mode` 选择后端，并负责 C 工具链与链接。
- `--emit-c` 且未指定 `--backend` 时走 MIR-C；默认（不指定 backend、不 emit C）走 LLVM。

## 3. 扩展语言

新增语法/语义通常需要按以下顺序改：

### 3.1 词法

- `mylc/src/lexer.rs`：增加 token、关键字、字面量扫描。
- 若是保留字，检查 parser 的关键字集合和诊断文案。

### 3.2 AST

- `mylc/src/ast.rs`：增加 `ExprKind` / `StmtKind` / `Type` / 注解等节点。
- 同步更新 `Display` / dump 实现，方便 `--emit-ir` 和调试。

### 3.3 语法

- `mylc/src/parser.rs`：解析新结构，补错误恢复。
- 保持“错误后尽量继续解析”的行为，避免一个语法错误吞掉整个文件。

### 3.4 语义

- `mylc/src/sema.rs`：符号解析、类型检查、可见性、初始化检查、诊断。
- 新诊断使用稳定的 `MYLxxx` 编号，并补 `tests/negative/` 用例。
- 不要在后端“补做”语义检查；后端只做 lowering 所需的布局检查。

### 3.5 MIR

- `mylc/src/mir.rs`：新增 `MirInstKind` / lowering。
- 如果指令有新的类型约束，更新 `mir::verify` 与 `mir/pass.rs`。
- `--emit-ir` 应能 dump 新指令，便于定位前端问题。
- 符号命名约定：包内声明的 MIR 名必须走 `mir::module_prefix`，入口模块 `<包名>::名字`，包子模块 `<包名>::<模块>::名字`；类型名与所在文件同名时不要重复模块段（`qualified_type_name` 已处理）。
- `.mylib` 合并要同时维护函数 id 与类型 id 映射，新增类型形态（新 `Type` / `Res` / `Pattern`）时同步 `MirProgram` JSON、`mylib::merge_into` 的 `rty`/`rres`/`rpat`/`rinst`。

### 3.6 后端

- C 后端：`mylc/src/codegen/*` 或 `backend/mir_c.rs`。
- LLVM 后端：`mylc/src/backend/llvm.rs` 的 `FnGen::inst` / `llty` / `emit` precheck。
- 未实现时返回明确错误，例如：

```rust
return Err(format!("LLVM 后端暂不支持 ..."));
```

### 3.7 测试

每个语言特性至少补：

- `tests/positive/<Name>.myl` + `.expected`
- 需要报错的补 `tests/negative/<Name>.myl`
- 如果 C / LLVM 都支持，补 `tests/test_backend_parity.sh` 对拍
- 如果只影响 LLVM，补 `tests/test_llvm.sh`

## 4. 新增后端

### 4.1 `Backend` trait

```rust
pub trait Backend {
    fn name(&self) -> &'static str;
    fn emit_exe(&self, prog: &Program) -> Artifact;
    fn emit_lib(&self, prog: &Program, mode: ExportMode) -> Artifact;
    fn header(&self, prog: &Program) -> String;
}
```

`Artifact`：

```rust
pub struct Artifact {
    pub kind: ArtifactKind,   // CSource | Ir | LlvmIr
    pub text: String,
    pub error: Option<String>,
}
```

新增后端步骤：

1. 在 `mylc/src/backend/` 新建实现，返回 `Artifact`。
2. 在 `backend/mod.rs` `pub use` 并增加 `ArtifactKind`（如目标文件/二进制）。
3. 在 `driver.rs` 的 `--backend` 分派中注册。
4. 在 `cli.rs` / `i18n.rs` 更新参数文档。
5. 若产物不是文本，`driver` 需要增加写文件/调用工具链的分支。
6. 增加独立测试脚本，不要只依赖 C 基线。

约定：

- `emit_lib` 不产生 `main`，应导出 `<stem>_init()`。
- `header` 只导出带 `@export` 的顶层函数。
- `Artifact.error` 必须是“后端明确拒绝”，不要用它承载部分成功。
- 后端名称保持小写、稳定，出现在 CLI 帮助和文档里。

## 5. 新增 C 工具链

工具链是**数据驱动**的，新增编译器通常不需要重编 `mylc`。

规格文件字段（`toolchains/*.toml` 或工程 `.mylis/toolchains/*.toml`）：

| 字段 | 含义 |
|---|---|
| `name` | 规格名 |
| `style` | `gnu` 或 `msvc` |
| `cc` | C 编译器命令 |
| `ar` | 归档器命令 |
| `cflags` / `ldflags` | 默认 C / 链接参数 |
| `include` | include 参数模板，如 `-I{path}` |
| `libdir` | 库目录参数模板，如 `-L{path}` |
| `link_lib` | 链接库参数模板，如 `-l{name}` |
| `obj_suffix` | 目标文件后缀 |
| `static_prefix` / `static_suffix` | 静态库前后缀 |
| `shared_prefix` / `shared_suffix` | 动态库前后缀 |
| `runtime` | `archive` 或 `sources` |

发现顺序：

1. 内置 `gcc` / `clang` / `msvc`
2. `~/.mylis/toolchains/*.toml`
3. `<安装根>/toolchains/*.toml`
4. `<工程>/.mylis/toolchains/*.toml`（最高）
5. `MYLIS_TOOLCHAINS` 指定目录

选择顺序：`MYLIS_FAMILY` → 工程 `[toolchain] family` → `mylis-toolchain.json` → 平台默认。
注意：这个顺序只决定“想用哪套规格”，不负责校验产物 ABI。

### 5.4 构建清单（强制一致性）

`make` 会在 `build/mylis-build.json` 生成当前产物的描述，并复制到 `bin/mylis-build.json`：

```json
{"schema":1,"os":"windows","family":"msvc","style":"msvc","abi":"msvc",
 "target":"x86_64-pc-windows-msvc","cc":"cl","ar":"lib",
 "myrt":"build/mylrt.lib","mylgc":"build/mylgc.lib",
 "simple":"build/gc_simple.lib",
 "system_libs":["ws2_32.lib","ntdll.lib","userenv.lib","advapi32.lib","bcrypt.lib","ole32.lib","oleaut32.lib","shell32.lib"]}
```

`mylc` 链接前读取它并检查：

- `os` 与当前平台一致；
- `abi` 与当前实际链接路径一致（LLVM Windows 也按 MSVC 运行时算）；
- `target` 与 MSVC/GNU ABI 匹配；
- `myrt` / `mylgc` 路径与 `Layout` 选择一致；
- 非 LLVM 后端时，清单里的 `cc` 家族与实际 `-cc` 一致；
- `system_libs` 决定 Windows 链入哪些系统库；`RT_NO_STD=1` 生成空数组，freestanding 运行时不会被迫链 `ws2_32/ntdll`；
- 同一份清单下，`cl` 直接传 `ws2_32.lib`，Windows LLVM 的 `clang` 传 `-lws2_32`；二者库搜索依赖 `LIB` 环境变量（vcvars64.bat）。

如果清单存在但不匹配，`mylc` 直接拒绝编译，避免把 `windows-gnu` 的运行时和 MSVC 主程序混链。清单缺失时保持旧包兼容。
`MYLIS_NO_MANIFEST=1` 只用于编译器自身的假 CC/AR 命令拼装测试，不要用于发布构建。

## 6. 运行时、GC 与平台扩展

### 6.1 三层 trait

```rust
pub trait Runtime: Sync {
    fn gc(&self) -> &dyn Gc;
    // 字符串、数组、打印、panic、数字格式化等默认实现
}

pub trait Gc: Send + Sync {
    fn init(&self);
    fn alloc(&self, size: usize) -> *mut u8;
    fn collect(&self);
    fn add_root_range(&self, start: *mut u8, len: usize);
    fn write_barrier(&self, value: *mut u8);
    fn write_barrier_owner(&self, owner_slot: *mut u8, value: *mut u8);
    // set_threshold / set_allocator 有默认空实现
}

pub trait Platform: Sync {
    fn write_stdout(&self, bytes: &[u8]);
    fn write_stderr(&self, bytes: &[u8]);
    fn abort(&self) -> !;
    fn clock(&self) -> f64;
    fn gc_threshold(&self) -> Option<usize>;
    fn format_f64(&self, v: f64) -> ([u8; 64], usize);
}
```

### 6.2 选择机制

`mylrt-rs/build.rs` 读取：

- `MYLRT_IMPL_RS`：运行时实现文件，默认 `src/impls/own.rs`
- `MYLRT_PLATFORM_RS`：平台实现文件，默认 `src/platforms/host.rs`

两个文件分别被 `include!` 成 `selected` / `selected_platform` 模块。

实现契约：

- 运行时文件必须提供 `pub fn runtime() -> &'static dyn Runtime`
- 平台文件必须提供 `pub fn platform() -> &'static dyn Platform`
- 自带 `Gc` 的裸机运行时用 `RT_NO_BACKEND_GC=1` 裁掉默认 `BackendGc`

### 6.3 Makefile 入口

```bash
make all RT_IMPL=own
make all RT_IMPL=boehm
make all RT_IMPL=simple
make all RT_IMPL=/path/to/runtime.rs
make all RT_IMPL=/path/to/rt_dir          # rt_dir/runtime.rs

make all RT_NO_STD=1
make all RT_NO_STD=1 PLATFORM_IMPL=/path/to/platform.rs
make all RT_NO_STD=1 RT_NO_BACKEND_GC=1 \
     RT_IMPL=/path/to/runtime.rs \
     PLATFORM_IMPL=/path/to/platform.rs
```

`RT_NO_STD=1` 使用 `--no-default-features`；`RT_NO_BACKEND_GC=1` 追加 `--features no-backend-gc`。

### 6.4 样例

- `mylrt-rs/examples/freestanding/`：Linux x86_64 无 libc，syscall + 固定 arena GC
- `mylrt-rs/examples/qemu-arm/`：Cortex-M3，semihosting + 固定 arena GC，QEMU `lm3s6965evb`

## 7. C ABI

### 7.1 头文件与布局

所有运行时代码只依赖 `myrt/mylrt.h`。核心类型：

```c
typedef struct MyStr MyStr;
struct MyStr {
    myrt_u64 len;
    char*    data;
};
```

约定：

- 字符串数据以 `len` 为准，运行时额外写一个 NUL 方便调试。
- 数组是裸指针：前 8 字节为 `myrt_u64 len`，元素从 `offset 8` 开始。
- 数组元素大小由后端按类型计算；引用类元素为 8 字节，接口值 16 字节。
- 类对象、枚举、接口值由后端布局，C 侧只应通过生成的库头文件或显式 FFI 类型访问。

### 7.2 运行时入口

常用符号：

| 符号 | 签名 | 用途 |
|---|---|---|
| `myrt_init` | `void myrt_init(void)` | 初始化 GC、根表、阈值 |
| `myrt_alloc` | `void* myrt_alloc(u64)` | GC 分配 |
| `myrt_str_lit` / `mylrt_str_lit` | `MyStr* (const char*, u64)` | 字符串字面量 |
| `mylrt_str_concat` | `MyStr* (MyStr*, MyStr*)` | 拼接 |
| `mylrt_str_eq` / `mylrt_str_cmp` | `i32` | 比较 |
| `mylrt_arr_alloc` | `void* (u64 elem_size, u64 len)` | 数组分配 |
| `mylrt_arr_index` | `u64 (u64 len, i64 idx)` | 越界检查 |
| `myrt_i64_to_string` / `myrt_u64_to_string` | `MyStr*` | 数字转字符串 |
| `myrt_f64_to_string` | `MyStr*` | 浮点转字符串 |
| `myrt_print` / `myrt_println` / `myrt_panic` | `void` | 输出/panic |
| `myrt_clock` | `double` | 秒级时钟 |
| `myrt_gc_safepoint` | `void` | 安全点轮询；编译器在调用/分配点插入 |
| `myrt_register_root` / `myrt_unregister_root` | `void` | 显式根对象注册，C ABI 手写代码可用 |
| `myrt_gc_*` | — | collect / barrier / stats |

新增一个运行时函数时要同步：

1. `myrt/mylrt.h`
2. `mylrt-rs/src/lib.rs` 的 `#[no_mangle] extern "C"` 壳
3. `mylc/src/backend/llvm.rs` 的 `runtime_sig` 和声明列表
4. `myrt/mylrt.c` 参考实现（如果保留）
5. C 后端 `codegen` 的调用点（若使用）
6. 测试

### 7.3 库模式导出

- 只导出顶层 `pub` 且带 `@export("name")` 的函数。
- LLVM 库后端生成一个与 `@export` 名字完全相同、无 `myl_` 前缀的包装函数，供 C 直接调用。
- 库初始化入口是 `<stem>_init()`；它会调用 `myrt_init()`，并在有静态字段时调用 `myl_init_statics()`。
- Windows 动态库包装函数带 `dllexport`。
- 参数仍走 `lib_ffi_ok`：标量、`Str`、`Ptr`、`Class`、`Iface`、`Array`；`Option` / `Result` / `Enum` 作为参数仍会被拒绝。
- 返回值走 `lib_ret_abi`：
  - 普通类型直接返回 LLVM 类型；
  - 8 字节 `Option` 返回 `i64`，把 tag 放低 32 位、payload 放高 32 位，
    对齐 C 侧“8 字节聚合打包进 RAX”的约定；
  - 16 字节 `Option` 直接返回 LLVM 聚合；16 字节 `Result` 返回 `{ i64, ptr }`，
    把 tag+ok 打包进第一个 eightbyte，避免 C 侧读 `RAX`/`RDX` 时错位；
  - 其他尺寸返回拒绝。`Result<i32,string>`、`Option<string>`、`Option<i64>`、
    `Option<i32>`、`Option<i8>`、`Option<f32>` 均已验证。
  - 这些规则按 x86-64 SysV（Linux/macOS clang/gcc）验证；MSVC 的小聚合 ABI
    不同，Windows 库导出暂不套用。
- 库头文件会为导出签名补 `MylO_*` / `MylR_*` 定义和类/枚举/接口前置声明。

## 8. LLVM ABI

LLVM 后端当前生成**文本 LLVM IR**，再交给 `clang` 编译。IR 里固定写：

```llvm
target triple = "x86_64-pc-linux-gnu"
```

如果以后要正式支持 Windows/MSVC 或多架构，需要把 target triple 变成参数，而不是继续写死。

### 8.1 类型映射

| Mylis 类型 | LLVM 类型 | 备注 |
|---|---|---|
| `i8/u8` | `i8` | 无符号性由操作/转换决定 |
| `i16/u16` | `i16` |  |
| `i32/u32` | `i32` |  |
| `i64/u64` | `i64` |  |
| `f32` | `float` |  |
| `f64` | `double` |  |
| `bool` | `i32` | 0/1 |
| `void` | `void` |  |
| `Str` | `ptr` | 指向 `MyStr` |
| `Class` | `ptr` | 指向 `%C_<id>` |
| `Array` | `ptr` | 指向带长度头的元素区 |
| `Ptr` | `ptr` |  |
| `Enum` | `%E_<id>` | 按值传递的聚合 |
| `Iface` | `%I_<id>` | `{ ptr, ptr }` |
| `Option<T>` | `%O_<type_key>` | `{ i32, T }`；`None=0`，`Some=1` |
| `Result<A,B>` | `%R_<type_key>` | `{ i32, A, B }`；`Err=0`，`Ok=1` |

`type_key` 是后端的稳定类型键，例如 `i32`、`str`、`c12`、`a i32`、`o i32`、`r i32_str`。新增类型时应保证键不冲突。

### 8.2 类与静态字段

```llvm
%C_<class_id> = type { <field0>, <field1>, ... }
```

- 只包含实例字段；字段顺序来自 `MirClass.fields`。
- 类值在 ABI 中是指向 `%C_<id>` 的指针。
- 静态字段：

```llvm
@S_<class_id>_<field_index> = global <field_type> zeroinitializer
```

- 静态初始化由 `myl_init_statics()` 完成，启动时调用。

### 8.3 枚举

```llvm
%E_<enum_id> = type { i32, [<max_variant_fields> x i64] }
```

- 字段 0 是 variant 下标。
- 字段 1 是统一 `i64` 载荷数组，构造时把各字段转成 `i64` 写入。
- 枚举的接口方法通过 `VTW_*` 包装函数把 `i64` 载荷还原成具体字段类型。

### 8.4 接口与 vtable

接口值：

```llvm
%I_<iface_id> = type { ptr, ptr }       ; { obj, vtable }
%Vt_<iface_id> = type { ptr, ptr, ... } ; 每个方法一个槽
```

- 空接口的 vtable 用 `{ i8 }` 占位，避免空聚合/空全局地址被合并。
- 方法槽顺序 = 接口声明中方法的顺序。
- 具体类/枚举实现接口时生成：

```llvm
@VT_<concrete_id>_<iface_id> = global %Vt_<iface_id> { ... }
```

- 枚举实现接口时，槽指向 `VTW_<enum>_<iface>_<slot>` 包装函数。
- 接口到接口的适配函数：

```llvm
define %I_<to> @IA_<from>_<to>(%I_<from> %v)
```

它按 vtable 指针做选择，生成目标接口的 `{obj, vtable}`。

### 8.5 Option / Result

```llvm
%O_<key> = type { i32, <T> }
%R_<key> = type { i32, <A>, <B> }
```

tag 约定：

| 类型 | tag |
|---|---|
| `None` | `0` |
| `Some` | `1` |
| `Err` | `0` |
| `Ok` | `1` |

- `Result` 的 `Err` 载荷在字段 2，`Ok` 载荷在字段 1。
- `Option<T>` / `Result<A,B>` 当前是显式聚合，不使用 union。
- `as?` 失败返回 `None`，`as` 失败走 panic。
- `Option<Iface>` / `Result<Iface>` 的接口值按 `%I_*` 布局存放。

### 8.6 数组

- `Array<T>` 在 LLVM 里是 `ptr`。
- 分配调用 `mylrt_arr_alloc(elem_size, len)`；返回内存前 8 字节是 `u64 len`。
- 下标访问调用 `mylrt_arr_index(len, idx)` 做负值和越界检查，然后按元素大小做 GEP。
- 元素大小（LLVM 后端当前实现）：

| 元素 | 字节 |
|---|---|
| `i8/u8/bool` | 1 |
| `i16/u16` | 2 |
| `i32/u32/f32` | 4 |
| `i64/u64/f64` | 8 |
| `Str/Class/Array/Ptr` | 8 |
| `Iface` | 16 |
| `Enum` | `8 + max_fields * 8` |
| `Option<T>` | 按 `{ i32, T }` 的自然对齐计算 |
| `Result<A,B>` | 按 `{ i32, A, B }` 的自然对齐计算 |

`Option`/`Result` 作为数组元素时，元素大小由 `size_align()` 按 LLVM 聚合布局计算，
例如 `Option<i32>` 为 8、`Result<i32, string>` 为 16。

### 8.7 函数与符号

- 内部函数符号：

```text
myl_<模块名/类名/方法名，非字母数字转下划线>
```

- 基本块标签：`L_<label>_<index>`。
- 函数参数按 Mylis 参数顺序直接映射；接收者作为第 0 个参数。
- `main` 只在可执行产物中生成：

```llvm
define i32 @main() {
entry:
  call void @myrt_init()
  call void @myl_init_statics()
  %r = call i32 @myl_...::main()
  ret i32 %r
}
```

- 可执行入口要求：`main` 返回 `i32`、无参数。
- 字符串字面量是私有全局常量，类型 `[len x i8]`，通过 `mylrt_str_lit` 转成 `MyStr*`。

### 8.8 运行时声明

LLVM 后端会为下列符号发射 `declare`：

```text
myrt_init, myrt_gc_collect, myrt_print, myrt_println, myrt_panic,
myrt_i64_to_string, myrt_u64_to_string, myrt_f64_to_string,
myrt_str_cstr, myrt_str_ptr, myrt_str_len, myrt_clock,
myrt_alloc, myrt_gc_write_barrier, myrt_gc_write_barrier_owner,
mylrt_arr_alloc, mylrt_arr_index,
mylrt_str_lit, mylrt_str_concat, mylrt_str_eq, mylrt_str_cmp,
mylrt_panic_unwrap, mylrt_panic_msg,
myrt_register_root, myrt_unregister_root, myrt_gc_safepoint,
myrt_gc_add_root_range, myrt_gc_remove_root_range,
myrt_gc_frame_enter, myrt_gc_frame_set_roots, myrt_gc_frame_exit,
myrt_gc_static_set_roots, myrt_gc_set_precise
```

新增/修改签名时必须同步 `runtime_sig` 与 `emit()` 里的声明列表，否则 LLVM 会在调用点类型不匹配。

### 8.9 GC 安全点

MIR 在 `Call` / `MethodCall` / `New` / `ArrayNew` / `ArrayLit` / `Interp` / `Box`
前插入 `safepoint roots=[...]`。roots 由反向活跃性数据流分析得到：只包含在该点之后
仍会被读取的 GC 引用型局部槽和 SSA 值，以及该调用自身的引用参数；不会包含
本次调用的 dst。
帧根采用“每个 safepoint 一张活跃根表”，而不是函数级并集。函数入口只做：

```llvm
%myl_roots = alloca [N x %MylRootDesc]   ; N = 该函数所有 safepoint roots 的并集大小
%myl_fid = call i64 @myrt_gc_frame_enter()
```

每个 `safepoint` 按当前 roots 快照填写描述符，再交给运行时：

```llvm
store ptr %lN, ptr %desc.start
store i64 <size>, ptr %desc.bytes
call void @myrt_gc_frame_set_roots(i64 %myl_fid, ptr %myl_roots, i64 <count>)
call void @myrt_gc_safepoint()
```

`count` 只包含该点真正活跃的根，之前的快照不会残留。每条 `ret` 前调用
`myrt_gc_frame_exit(%myl_fid)`。MIR-C 生成同一套逻辑的 C 代码：
`myrt_gc_frame_id myl_fid = myrt_gc_frame_enter();`、`myrt_gc_root_desc
myl_roots[N];`，在每个 safepoint 填 `&lN` / `&vN` 与 `sizeof(...)` 后调用
`myrt_gc_frame_set_roots`。静态引用字段仍通过 `myrt_gc_add_root_range` 注册到
全局根表，不进入帧表。

运行时默认仍保守扫描线程栈；设置 `MYLIS_GC_PRECISE=1` 后 `mylgc` 只扫描静态
根区间与所有 active frame 的当前根表，不扫描线程栈。AST-C 回退路径不保证帧根
完整，因此精确模式只应在 LLVM / MIR-C 上使用。

### 8.10 写屏障与 remembered set

所有堆引用写入都调用 `myrt_gc_write_barrier_owner(owner_slot, value)`：
`owner_slot` 是写入位置（对象字段/数组元素的地址），GC 用 `find_block(owner_slot)`
反查所属对象。若所属对象是老年代、且新值是年轻代对象，就把 owner 记进
**remembered set**；minor 只扫描 remembered set 中的老年代对象，不再扫描整个
老年代。老年代对象在 minor 中无条件保留，major 才按标记回收。

新增根区间 API 时必须同步 `Gc` trait、`BackendGc`、`mylrt` C ABI、
`mylgc` 的 `roots.rs`/`mark.rs`，以及 `llvm.rs` 的 `runtime_sig` 与声明表。

### 8.10 库模式

- `emit_lib` 调用 `emit(ir, false)`，不生成 `main`。
- 额外生成 `<stem>_init()`。
- 对每个 `@export` 函数生成无 `myl_` 前缀的 C ABI 包装。
- `lib_ffi_ok` 决定哪些类型可以跨库边界；新增类型时先决定它是否有稳定 C ABI。
- 头文件由 `codegen::header_text` 生成，C 类型来自 `ctype` 映射（`myrt_i*`、`MyStr*`、`MylO_*` 等）。

### 8.11 LLVM ABI 修改清单

改 ABI 时至少检查：

- `mylc/src/backend/llvm.rs` 的类型/布局/声明
- `myrt/mylrt.h` 与 `mylrt-rs/src/lib.rs`
- `myrt/mylrt.c` 参考实现
- `mylc/src/codegen/names.rs` 的 C 类型映射
- 库模式头文件
- `tests/test_llvm.sh`、库模式测试、对拍测试
