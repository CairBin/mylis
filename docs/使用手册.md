# Mylis 使用手册

本手册面向使用 `mylc` 编译 Mylis 程序、构建 Mylis 工程、调用 Mylis 库的开发者。语言语法见 [`Mylis语言规范.md`](Mylis语言规范.md)，编译器内部结构见 [`开发者指南.md`](开发者指南.md)。

---

## 1. 环境要求

| 用途 | 要求 |
|---|---|
| 构建 `mylc` / `myls` | Rust 工具链（`cargo`） |
| 默认 LLVM 后端 | LLVM 15 及以上的 `clang`；驱动会自动优先寻找 `clang-20` … `clang-15` |
| Linux / macOS C 后端 | GCC 兼容 `cc` / `ar` |
| Windows C 后端 | Visual Studio Build Tools 的 `cl.exe` / `lib.exe`，并在 VS 开发者命令提示符或已执行 `vcvars64.bat` 的环境中构建 |
| 测试 | GNU make、Python 3、LLVM 15+（跑 `test_llvm.sh` 需要） |

默认运行时是 Rust 实现的 `mylrt` + 自研 GC（`mylgc`），不需要 Boehm GC。只有显式使用 Boehm 时才需要先执行 `make bootstrap`。

## 2. 从源码编译编译器

### 2.1 快速构建

```bash
cd <mylis 源码根目录>
make all
```

`make all` 会构建：

- `build/mylc`、`build/myls`
- `build/libmylrt.a`（Unix）或 `build/mylrt.lib`（Windows MSVC）
- `build/libmylgc.a` / `mylgc.lib`
- 可选的 `build/libgc_simple.a`、`build/libgc_boehm.a`
- 把上述内容收进自足的 `bin/`

`bin/` 可以直接整体拷走使用：

```text
bin/
├── mylc
├── myls
├── std/
├── myrt/
├── gc/
├── toolchains/
└── build/
```

如果只拷贝 `mylc` 而不带 `bin/` 下的运行时，需要设置 `MYLIS_ROOT` 指向包含 `myrt/mylrt.h` 的安装根目录。

### 2.2 make 目标

| 目标 | 作用 |
|---|---|
| `make` / `make all` | 构建编译器、语言服务器、运行时和 GC，收进 `bin/` |
| `make mylc` | 只构建 `build/mylc` |
| `make myls` | 只构建 `build/myls` |
| `make myrt` | 只构建 Rust 运行时静态库 |
| `make test` | 跑完整回归（C 基线、对拍、MIR、LLVM、库模式、工具链、运行时、LSP） |
| `make bootstrap` | 下载并编译 Boehm GC（可选） |
| `make clean` | 删除 `build/`、`bin/`、`mylc/target/` 和 `mylgc/target/` |
| `make dist` | Windows 发行包（需要在 Windows + MSVC 环境执行，内部调用 `tools/package_windows.ps1`） |

### 2.3 make 参数

#### 编译器与工具链

| 参数 | 默认值 | 说明 |
|---|---|---|
| `CARGO` | `cargo` | Rust 构建命令 |
| `CC` | Unix `gcc` / Windows `cl` | 编译 C 代码、GC 后端和 `mylrt.c` 参考实现 |
| `AR` | Unix `ar` / Windows `lib` | 归档静态库 |
| `CARGO_TARGET` | Windows `x86_64-pc-windows-msvc`，Unix 空 | Rust 交叉目标 |
| `GC_ROOT` | `$HOME/mylis-toolchain` | Boehm GC 的 include/lib 根目录 |

`make GC_BACKEND=...` 和 `make BACKEND=...` 目前只影响 `bin/` 构建提示，不会改变 `mylc` 的默认行为。真正选择 GC 和后端的方式见第 6、9 节。

#### 运行时实现选择

| 参数 | 默认值 | 说明 |
|---|---|---|
| `RT_IMPL` | `own` | `own` / `boehm` / `simple`，或一个 `.rs` 实现文件，或包含 `runtime.rs` 的目录 |
| `RT_IMPL_DIR` | `mylrt-rs/src/impls` | 按名字查找 `<name>.rs` 的目录 |
| `RT_NO_STD` | 空 | 非空时用 `#![no_std]` 构建运行时 |
| `RT_NO_BACKEND_GC` | 空 | 非空时裁掉默认 `BackendGc`，适用于自带 `Gc` 的裸机运行时 |
| `PLATFORM_IMPL` | `host` | 平台实现：`host`、`.rs` 文件，或包含 `platform.rs` 的目录 |
| `PLATFORM_IMPL_DIR` | `mylrt-rs/src/platforms` | 按名字查找 `<name>.rs` 的目录 |

常见组合：

```bash
make all
make all RT_IMPL=boehm
make all RT_IMPL=/path/to/runtime.rs
make all RT_IMPL=/path/to/rt_dir

make all RT_NO_STD=1
make all RT_NO_STD=1 PLATFORM_IMPL=/path/to/platform.rs
make all RT_NO_STD=1 RT_NO_BACKEND_GC=1 \
     RT_IMPL=/path/to/runtime.rs \
     PLATFORM_IMPL=/path/to/platform.rs
```

第三方实现文件的最小契约、`Platform` 接口和裸机样例见 [`../mylrt-rs/README.md`](../mylrt-rs/README.md) 与 `mylrt-rs/examples/`。

### 2.4 Windows / MSVC 构建

在 **x64 Native Tools Command Prompt for VS**（或已执行 `vcvars64.bat` 的 shell）里：

```bat
set CC=cl
set AR=lib
make all
```

Windows 分支默认强制 `CC=cl`、`AR=lib`，会覆盖终端继承的 `CC=cc` / `AR=ar`；
命令行仍可用 `make CC=clang-cl`，显式 `make CC=cc` 会拒绝。`make test-win` 也会锁定并在结束后恢复。

默认会使用：

- Rust 目标 `x86_64-pc-windows-msvc`
- C 编译器 `cl.exe`
- 归档器 `lib.exe`
- 运行时 `build/mylrt.lib`，GC 为 `build/mylgc.lib`

Linux/macOS 默认使用 GCC；Windows 当前只允许 MSVC 构建族：

```bat
make all TOOLCHAIN_FAMILY=msvc
make all CC=clang-cl
```

如果 `TOOLCHAIN_FAMILY` 不是 `msvc`，或 `CARGO_TARGET` 不是 `*-windows-msvc`，Makefile 会直接报错，
不会生成“编译器是 GNU、运行时却是 MSVC”的混合产物。

构建一致性检查：

```bat
make check-toolchain   :: cl.exe/lib.exe/cargo 是否可用
make check-rt          :: 用当前 CC 链接 myrt + mylgc 并运行探针
```

`mylc` 链接前会读取 `mylis-build.json`，校验 ABI、target 和运行时库路径。

默认 LLVM 后端在运行时还需要 `clang`。如果 `clang` 不在 PATH，`mylc` 会报“无法启动编译器 `clang`”。

Windows 冒烟测试：

```bat
make test-win
```

或直接运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools\test_windows.ps1`。脚本会自动加载 `vcvars64.bat`（也可用 `-VcVars` 指定），检查 MSVC/Rust target，构建 `bin/`，测试默认 LLVM、MIR-C、AST-C、`.mylib`，并验证发行 zip 的 `core/`、`std/src/` 与运行时库布局。

## 3. 编译单个 Mylis 文件

### 3.1 基本用法

```bash
bin/mylc app.myl
bin/mylc app.myl -o out/app
bin/mylc app.myl --run
bin/mylc app.myl --check
```

不指定 `-o` 时，可执行文件默认取入口文件名（Windows 自动加 `.exe`）。

### 3.2 全部命令行参数

| 参数 | 说明 |
|---|---|
| `-o <path>` / `--out <path>` | 指定产物路径 |
| `--static` / `--lib` / `--static-lib` | 生成静态库和配套头文件 |
| `--shared` / `--dylib` | 生成动态库和配套头文件 |
| `--embed-runtime` | 动态库内嵌运行时；默认 Windows 内嵌，Linux 不内嵌 |
| `--emit-c <path>` | 只生成文本；默认 MIR-C 后端，不要和 `--backend llvm` 混用 |
| `--emit-ir <path>` | 只生成 MIR 文本（`.myl.ir`） |
| `--emit-llvm <path>` | 只生成 LLVM IR 文本（`.myl.ll`） |
| `--emit-mylib <path>` | 生成后端无关的 MIR 库（`.mylib`），不调用 C/LLVM 工具链 |
| `--embed-static <path>` | 与 `--emit-mylib` 联用，把静态库嵌入归档；消费方链接归档时使用该库 |
| `--embed-shared <path>` | 与 `--emit-mylib` 联用，把动态库嵌入归档；消费方链接归档时使用该库 |
| `--link-mylib <path>` | 链接 `.mylib`，可重复；支持可执行/静态库/动态库产物，API 覆盖函数、类型和子模块 |
| `--backend <name>` | 选择后端，见 3.3 |
| `--check` | 只做语法和语义检查，不生成产物 |
| `--update-lock` | 重新解析依赖并重写 `mylis.lock` |
| `--offline` | 离线构建：不 fetch Git、不下载 `.mylib`，只使用已有缓存 |
| `-I <dir>` | 追加模块搜索路径，可多次 |
| `-l <name>` | 链接名为 `name` 的库，可多次 |
| `-L <dir>` | 追加库搜索目录，可多次 |
| `--link <file>` | 直接链接一个 `.a` / `.o` / `.dll` / `.lib`，可多次 |
| `--cc <program>` | 覆盖 C 编译器（等价于 `MYLIS_CC`） |
| `--lang zh\|en` | 编译器自身诊断语言，默认简体中文 |
| `--run` | 编译后立即运行 |
| `-v` / `--verbose` | 打印模块拓扑、后端阶段和外部工具命令行 |
| `-h` / `--help` | 显示帮助 |

### 3.3 后端选择

| 选择方式 | 实际后端 |
|---|---|
| 不指定 `--backend`，也不指定 `--emit-c` | LLVM（默认） |
| `--backend llvm` | LLVM |
| `--backend mir` | MIR → C（MIR-C） |
| `--backend ast` / `--backend c` | AST → C（兼容回退） |
| `--backend ir` | MIR 文本后端（内部/实验用途） |
| `--emit-c` | 不指定 `--backend` 时走 MIR-C；若同时指定 `--backend`，按指定后端生成文本（不推荐混用） |
| `--emit-llvm` | 只输出 LLVM IR，不编译可执行文件 |
| `--emit-ir` | 只输出 MIR 文本，不编译可执行文件 |
| `--emit-mylib` | 只输出 `.mylib` MIR 库归档 |

工程也可以在 `mylis.toml` 的 `[build] backend` 固定后端。

## 4. 工程构建：`mylis.toml`

### 4.1 最小工程

```toml
[project]
name = "hello"
version = "0.1.0"

[build]
paths = ["src", "lib"]
backend = "llvm"

[targets.hello]
kind = "exe"
entry = "src/main.myl"
out = "build/hello"
```

- `[build] paths` 是模块搜索根，按顺序查找；默认 `["src", "lib"]`。
- `[build] backend` 可选：`llvm`（默认）、`mir`、`ast`、`ir`。
- `[targets.<name>]` 的 `kind` 为 `exe` / `static` / `shared`。
- `entry` 是目标入口文件，``out`` 省略时默认为 `build/<target 名>`。
- `[toolchain]` 段可以写 `family` / `cc` / `ar`，详见 4.4。

包模式推荐把 `[project]` 换成 `[package]`，并用 `[lib]` 声明库入口：

```toml
[package]
name = "mathlib"
version = "0.1.0"

[lib]
entry = "src/lib.myl"

[dependencies]
core = "../core"
# 或 core = { path = "../core" }
# registry 依赖：版本约束 + registry 名
log = { version = "^0.1.0", registry = "default" }
# Git 依赖：用户手写仓库 URL，不发布、不维护 registry
mathlib = { git = "https://github.com/you/mathlib", tag = "v0.1.0" }
# 也可用 rev / branch
# mathlib = { git = "https://github.com/you/mathlib", rev = "a1b2c3d" }
# .mylib 依赖：直接指向 MIR 归档；checksum 可选但建议写
mathlib = { mylib = "https://github.com/you/mathlib/releases/download/v0.1.0/mathlib.mylib", checksum = "sha256-..." }
# 本地归档也支持
# mathlib = { mylib = "lib/mathlib.mylib" }
```

应用包使用同样的依赖写法。加载依赖包后，**模块导入本身不绑定裸名**：

```mylis
import "mathlib";                 // 只加载 mathlib；调用写 mathlib::add(1, 2)
import "mathlib/vector";          // 多段模块；调用写 mathlib::vector::triple(4)
import { add } from "mathlib";    // 选择性导入；之后可以裸写 add(1, 2)
import { triple } from "mathlib/vector";
```

`import "mathlib"` 会加载依赖包的 `[lib] entry`；`import "mathlib/vector"` 会查找依赖包 `src/vector.myl`。

两个包都有 `ADD` 时：

```mylis
import "A";
import { ADD } from "B";

fn main() -> i32 {
    A::ADD(1, 2);   // 合法：A 只加载模块，必须限定
    ADD(1, 2);      // 合法：来自 B 的选择性导入
    B::ADD(1, 2);   // 也合法
    return 0;
}
```

如果两个都写 `import { ADD }`，第二个导入行直接报 `MYL011`（显式导入名重复）。
需要裸名时只能选一个；另一个必须用包名限定。

registry 默认根目录是 `~/.mylis/registry`，布局为 `<registry>/<包名>/<版本>/mylis.toml`。可用 `MYLIS_REGISTRY` 覆盖默认目录；命名 registry 用 `MYLIS_REGISTRY_<NAME>`（大写，`-` 换成 `_`）。版本约束支持 `*`、`^1.2.0`、`~1.2.0`、`=1.2.3`。

Git 依赖会把仓库 clone 到 `~/.mylis/git/db/`，按解析出的 commit 检出到 `~/.mylis/git/checkouts/`，可以用 `MYLIS_GIT_CACHE` 改缓存根。`tag` / `rev` / `branch` 只用于首次解析，锁文件记录的是精确 commit；tag 移动后已有锁不会变，执行 `--update-lock` 才会重新解析。

`.mylib` 依赖直接消费 MIR 归档，不需要源码或 `mylis.toml`。远程 URL 会用 `curl` 下载到 `~/.mylis/mylib/downloads/`，可用 `MYLIS_MYLIB_CACHE` 改缓存根；本地路径相对当前清单目录解析。锁文件记录归档的 SHA-256，归档被替换或损坏会报 checksum 不一致。`--link-mylib` 支持可执行/IR/C 源产物；带原生载荷的 `.mylib` 可直接参与可执行、静态库和动态库链接。原生载荷使用归档声明的 C ABI 符号名；`--backend mir`（C 后端）和默认的 `--backend llvm` 都支持消费，LLVM 后端会为 API 顶层函数生成 `declare` 并直接链接原生库。`--offline` 会让 Git 和远程 `.mylib` 只查缓存，缺缓存时直接报错。

首次构建会在包根生成 `mylis.lock`。锁文件存在时，mylc 会按锁定的版本/源解析依赖，并重新计算依赖包 checksum；版本、源或 checksum 与锁不一致会报错，必须显式运行 `--update-lock` 才重写。

### 4.2 构建命令

```bash
mylc build              # 构建全部目标
mylc build hello        # 只构建 hello
mylc build --update-lock # 重新解析依赖并重写 mylis.lock
mylc build --offline     # 只用缓存中的 Git/.mylib，不联网
mylc run hello          # 构建后运行 hello
mylc test               # 编译并运行 tests/**/*.myl，比对同名 .expected
mylc src/lib.myl --emit-mylib build/mathlib.mylib   # 生成后端无关的 MIR 库
mylc src/main.myl --link-mylib build/mathlib.mylib  # 链接 .mylib，可直接调用其 pub fn / pub class / pub enum

# 生成带原生载荷的 .mylib：先构建 .a/.so，再嵌入归档
mylc src/lib.myl --emit-mylib build/mathlib.mylib --embed-static build/libmathlib.a
mylc src/lib.myl --emit-mylib build/mathlib.mylib --embed-shared build/libmathlib.so

# 消费带原生载荷的 .mylib（C 后端或 LLVM 后端均可）
mylc src/main.myl --link-mylib build/mathlib.mylib --backend llvm -o app
mylc src/main.myl --link-mylib build/mathlib.mylib --backend mir -o app
mylc src/main.myl --link-mylib build/mathlib.mylib --backend mir --static -o libapp.a
mylc src/main.myl --link-mylib build/mathlib.mylib --backend mir --shared -o libapp.so
```

`.mylib` 的 API 段会导出根包的 `pub fn`、`pub class`、`pub enum`、`pub interface`、`pub type`；类的公开字段、构造器、公开方法，枚举变体，接口方法都可直接使用。归档按模块保存 API：`import "mathlib"` 用根 API，`import "mathlib/vector"` 用子模块 API。依赖包类型以包名限定，例如 `dep::Foo`；类型所在模块与类型同名时不再重复模块段，否则写成 `dep::vector::Foo`。使用限定类型时，用户模块必须显式写 `import "dep/Foo";`（不是只写 `import "dep";`），库生成的 API 模块才允许自动看见全部依赖模块。因此跨包返回 class/enum/interface 也能解析，同名类型不会互相覆盖。

`mylc build` 会从当前目录向上查找 `mylis.toml`；找到后切换到工程根执行目标。

### 4.3 模块搜索顺序

1. 安装根下的 `std/`
2. `mylis.toml` 的 `[build] paths`（相对工程根）
3. 命令行 `-I`
4. `MYLIS_PATH` 中的目录（Windows 用 `;`，其他平台用 `:` 分隔）

以上都找不到时，按当前模块最近的 `mylis.toml` 的 `[dependencies]` 做包名解析。同一包名只允许一个路径/版本：菱形依赖同源同版本会自动去重，同名不同路径或版本会报依赖冲突。

### 4.4 工具链选择

工具链规格按以下顺序加载：

1. 内置 `gcc` / `clang` / `msvc`
2. `~/.mylis/toolchains/*.toml`
3. `<安装根>/toolchains/*.toml`
4. `<工程>/.mylis/toolchains/*.toml`（优先级最高）
5. `MYLIS_TOOLCHAINS` 指定的目录

选择哪个规格：

1. 环境变量 `MYLIS_FAMILY`
2. 工程 `mylis.toml` 的 `[toolchain] family`
3. 随包 `mylis-toolchain.json` 的 `family`
4. 默认：Windows `msvc`，其他平台 `gcc`

字段还可以用 `MYLIS_CC`、`MYLIS_AR`、`MYLIS_CFLAGS`、`MYLIS_LDFLAGS` 覆盖。

一个自定义规格示例：

```toml
name = "zig-gcc"
style = "gnu"
cc = "zig cc"
ar = "ar"
cflags = ["-O2", "-fPIC"]
ldflags = ["-lm"]
runtime = "archive"
```

（实际文件名放在 `toolchains/<name>.toml` 或工程 `.mylis/toolchains/<name>.toml`。）

### 4.5 标准库：Vec<T>

`std/src/Vec.myl` 提供编译期单态化的动态数组：

```myl
import { println_i64 } from "Io.myl";
import { Vec } from "Vec.myl";

fn main() -> i32 {
    Vec<i64> v = new Vec(); // 由左侧类型推断 T=i64
    v.push(10);
    v.push(20);
    println_i64(v.len());
    println_i64(v.get(0));
    return 0;
}
```

`Vec<T>` 的元素类型 `T` 必须是值类型；同一容器不能混存不同类型，也不使用 `Any` 装箱。
`push` / `pop` 均摊 O(1)，`get` / `set` 为 O(1)。

当前 API：

- `push(v)`、`pop() -> Option<T>`
- `get(i)`、`set(i, v)`
- `first() -> Option<T>`、`last() -> Option<T>`
- `insert(i, v)`、`remove(i) -> Option<T>`
- `clear()`、`reserve(n)`
- `truncate(n)`、`resize(n, value)`
- `swap(i, j)`、`reverse()`
- `extend(other)`：把另一个 `Vec<T>` 的元素追加到当前容器
- `capacity()`：返回当前已分配容量
- `len()`、`isEmpty()`

`insert` 的合法范围是 `0..len`，越界为 no-op；`remove` 越界返回 `None`。
`truncate` 只缩小长度；`resize` 缩小时截断，扩大时用给定值填充。
`clear()` 只清长度，保留已分配的容量；本版没有迭代器 API。
`new Vec()` 这类没有构造参数的实例依赖左侧/上下文中的具体类型来推断 `T`；无法推断时需要写 `new Vec<i64>()`。

### 4.5.1 标准库：Map<K, V> 与 Set<T>

`std/src/Map.myl` 提供线性查找的泛型键值表，只要求 `K: Eq`：

```myl
import { Map } from "Map.myl";

fn main() -> i32 {
    Map<string, i64> ages = new Map<string, i64>();
    ages.set("a", 1);
    ages.set("b", 2);
    match ages.get("a") {
        Some(v) => { /* v = 1 */ }
        None => {}
    }
    ages.remove("a");
    return 0;
}
```

API：

- `set(key, value)`：存在则覆盖，不存在则插入
- `insert(key, value) -> bool`：存在则覆盖并返回 `false`，不存在则插入并返回 `true`
- `get(key) -> Option<V>`、`getOr(key, fallback) -> V`、`containsKey(key) -> bool`
- `remove(key) -> Option<V>`、`clear()`
- `keys() -> Vec<K>`、`values() -> Vec<V>`
- `len()`、`isEmpty()`
- `keys` / `values` 是公开数组字段，有效范围是 `0..len()`

第一版是线性表，查找/插入/删除均为 O(n)，没有实现哈希；`Map<Any, V>` 这种装箱键不可用。

`std/src/Set.myl` 提供基于数组的线性集合，只要求 `T: Eq`：

```myl
import { Set } from "Set.myl";

fn main() -> i32 {
    Set<i64> values = new Set<i64>();
    values.add(1);       // true
    values.add(1);       // false
    values.remove(1);    // true
    return 0;
}
```

API：

- `add(v) -> bool`、`remove(v) -> bool`
- `contains(v) -> bool`
- `addAll(other)`、`removeAll(other)`、`retainAll(other)`（原地并/差/交）
- `containsAll(other) -> bool`
- `union(other) -> Set<T>`、`intersection(other) -> Set<T>`、`difference(other) -> Set<T>`（返回新集合，不修改任一操作数）
- `get(i) -> Option<T>`、`toVec() -> Vec<T>`
- `len()`、`isEmpty()`、`clear()`

`Set` 同样是线性查找，O(n)。`keys` / `values` / `toVec` 以及 `union` / `intersection` / `difference` 返回新容器，不共享原表存储。

#### Queue 与 Stack

`std/src/Queue.myl` 提供基于 `Vec<T>` 的先进先出队列：

```myl
import { Queue } from "Queue.myl";
Queue<i64> q = new Queue<i64>();
q.enqueue(1);
q.enqueue(2);
match q.dequeue() { Some(v) => { /* v = 1 */ } None => {} }
```

API：`enqueue(v)`、`dequeue() -> Option<T>`、`peek() -> Option<T>`、`len()`、`isEmpty()`、`clear()`。
队列用 `head` 下标避免每次出队搬移；出队积累到一定数量后自动压缩底层数组。

`std/src/Stack.myl` 提供后进先出栈：

```myl
import { Stack } from "Stack.myl";
Stack<i64> s = new Stack<i64>();
s.push(1);
s.push(2);
match s.pop() { Some(v) => { /* v = 2 */ } None => {} }
```

API：`push(v)`、`pop() -> Option<T>`、`peek() -> Option<T>`、`len()`、`isEmpty()`、`clear()`。

`std/src/Deque.myl` 提供双端队列：

```myl
import { Deque } from "Deque.myl";
Deque<i64> d = new Deque<i64>();
d.pushBack(2);
d.pushFront(1);
match d.popFront() { Some(v) => { /* v = 1 */ } None => {} }
```

API：`pushFront(v)`、`pushBack(v)`、`popFront() -> Option<T>`、`popBack() -> Option<T>`、`peekFront() -> Option<T>`、`peekBack() -> Option<T>`、`len()`、`isEmpty()`、`clear()`、`toVec() -> Vec<T>`。
`Deque` 用 front/back 两个 `Vec<T>`，只在需要时把一侧倒到另一侧，均摊 O(1)。

### 4.5.2 标准库：Algorithms

`std/src/Algorithms.myl` 提供不依赖迭代器的自由函数：

```myl
pub fn contains<T: Eq>(Vec<T> values, T value) -> bool;
pub fn index_of<T: Eq>(Vec<T> values, T value) -> i64;
pub fn sort<T: Ord>(Vec<T> values) -> void;
pub fn extend<T>(Vec<T> values, Vec<T> other) -> void;
pub fn binary_search<T: Ord>(Vec<T> values, T value) -> Option<i64>;
pub fn is_sorted<T: Ord>(Vec<T> values) -> bool;
```

`sort` 是原地稳定插入排序，O(n^2)；`extend` 把 `other` 的元素逐个追加到 `values`。
`binary_search` 只对已排序序列有效，返回匹配元素的下标；未找到返回 `None`，重复元素返回其中一个匹配位置。
`is_sorted` 判断序列是否按 `Ord` 非递减，空序列和单元素序列返回 `true`。
`min` / `max` 仍在 `core/Compare.myl`，不在 `Algorithms`。

### 4.5.3 标准库：Text（纯 Mylis）

`std/src/Text.myl` 提供不访问文件系统的文本切分、拼接、按行拆分与整数解析：

```myl
import { Text } from "Text.myl";
import { Vec } from "Vec.myl";

fn main() -> i32 {
    Vec<string> parts = Text::Split("a,b,,c", ",");
    // parts = ["a", "b", "", "c"]
    Vec<string> lines = Text::Lines("a\r\nb\n");
    // lines = ["a", "b"]
    string joined = Text::Join(parts, "|");
    // joined = "a|b||c"
    match Text::ParseI64(" -42 ") {
        Some(v) => { /* v = -42 */ }
        None => {}
    }
    return 0;
}
```

API：

- `Split(value, sep) -> Vec<string>`
- `Join(parts, sep) -> string`
- `Lines(value) -> Vec<string>`
- `ParseBool(value) -> Option<bool>`
- `ParseI64(value) -> Option<i64>`
- `ParseU64(value) -> Option<u64>`
- `Concat(left, right) -> string`、`Equals(left, right) -> bool`、`Compare(left, right) -> i32`
- `Len(value) -> u64`、`ByteLen(value) -> u64`、`IsEmpty(value) -> bool`
- `StartsWith`、`EndsWith`、`Contains`、`IndexOf`
- `Trim`、`Substring`、`CharAt`、`CharCodeAt`
- `Repeat`、`Replace`、`Bytes`、`FromBytes`

`ParseBool` 在 `Trim` 后只接受 `"true"` / `"false"`，其他输入返回 `None`。
`Split` 按字符匹配分隔符，支持多字符分隔符；分隔符为空串时返回只含原值的单元素 `Vec`，尾部分隔符保留末尾空段。
`Lines` 按 `\n` 切分，剥离每段末尾的 `\r`，并丢弃末尾空行；空输入返回空 `Vec`。
`ParseI64` / `ParseU64` 先做 `Trim`；允许前导 `+`，`ParseI64` 允许 `-`。存在非数字字符或数值溢出时返回 `None`。支持 `i64` 两端边界（含最小值 `-9223372036854775808`）。

`std/src/StringBuilder.myl` 提供分片累积的文本构建器：

```myl
import { StringBuilder } from "StringBuilder.myl";
StringBuilder b = new StringBuilder();
b.append("ab");
b.appendLine("cd");
println(b.toString());   // "ab" + "cd\n"
```

API：`append(text)`、`appendLine(text)`、`len()`（按字符计）、`isEmpty()`、`clear()`、`toString()`。
`toString()` 会把所有片段拼接成新字符串，原 builder 不会被修改。

### 4.5.4 标准库：Stdio（hosted，需要 native 后端）

`std/src/Stdio.myl` 提供命令行程序需要的标准输入与进程接口。它和纯输出的 `Io` 分开，避免只用
`Io::Println` 的程序被迫链接 stdio 原生库。

```myl
import { Stdio } from "Stdio.myl";

fn main() -> i32 {
    Option<string> line = Stdio::ReadLine();
    match line {
        Some(text) => { println(text); }
        None => { /* EOF 或读错误 */ }
    }
    Vec<string> args = Stdio::Args();   // 含 argv[0]（程序名）
    Option<string> home = Stdio::Env("HOME");
    return 0;
}
```

API：

- `Stdio::ReadLine() -> Option<string>`：阻塞读一行，去掉行尾 `\n` / `\r\n`；EOF 或读错误返回 `None`
- `Stdio::ReadAll() -> Option<string>`：读取 stdin 剩余内容；EOF 返回空串，读错误返回 `None`
- `Stdio::Args() -> Vec<string>`：命令行参数，`Args().get(0)` 是程序名
- `Stdio::Env(key) -> Option<string>`：环境变量；变量存在但值为空时返回 `Some("")`
- `Stdio::Exit(code)`：立即结束进程，不执行后续 Mylis 语句

native 后端是 `std-posix/native/io.rs` 与 `mylis_io.h`。`--std` 会自动链接
`libmylis_file.a`、`libmylis_io.a`、`libmylis_time.a`、`libmylis_net.a`、`libmylis_event.a` 与 `libmylis_process.a`；手工编译时至少需要：

```bash
./build/mylc src/main.myl -I std/src -I std-posix/native \
  --link build/std-posix/native/libmylis_io.a -o build/app
```

### 4.5.5 标准库：File（hosted，需要 native 后端）

`std/src/File.myl` 提供阻塞文件 API，错误统一为 `IoError` / `IoErrorKind`：

```myl
import { File } from "File.myl";
import { IoError } from "IoError.myl";

fn main() -> i32 {
    Result<File, IoError> made = File::Create("build/demo.txt");
    match made {
        Ok(f) => {
            f.writeAllText("hello");
            f.close();
        }
        Err(e) => { /* e.kind / e.code / e.message */ }
    }
    return 0;
}
```

API：

- `File::Open(path) -> Result<File, IoError>`：只读打开
- `File::Create(path) -> Result<File, IoError>`：写打开，存在则截断
- `File::Append(path) -> Result<File, IoError>`：追加打开，不存在则创建
- `readAllBytes() -> Result<u8[], IoError>`、`readAllText() -> Result<string, IoError>`
- `readSome(maxBytes) -> Result<u8[], IoError>`：从当前位置最多读 `maxBytes` 字节；EOF 返回空数组
- `writeAllBytes(u8[]) -> Result<i64, IoError>`、`writeAllText(string) -> Result<i64, IoError>`
  - 返回实际写入字节数；编译器目前不支持 `Result<void, E>`，所以不是 `Result<void, IoError>`
- `seek(offset) -> Result<i64, IoError>`、`tell() -> Result<i64, IoError>`
- `flush() -> Result<i64, IoError>`
- `close()`：显式关闭；GC 不负责关闭文件句柄
- `File::Exists(path) -> bool`、`File::IsDir(path) -> bool`
- `File::Size(path) -> Result<i64, IoError>`：路径对应的文件/目录元数据大小
- `File::Mkdir(path) -> Result<i64, IoError>`、`File::MkdirAll(path) -> Result<i64, IoError>`
- `File::Remove(path) -> Result<i64, IoError>`：只删文件，不删目录
- `File::RemoveDir(path) -> Result<i64, IoError>`：只删空目录
- `File::RemoveDirAll(path) -> Result<i64, IoError>`：递归删除目录
- `File::ReadDir(path) -> Result<Vec<string>, IoError>`：按文件名字典序返回目录项（不含路径前缀）
- `File::Rename(from, to) -> Result<i64, IoError>`

`readAll*` 会先把文件位置复位到 0，再读整个文件；`readSome` 从当前位置继续读，`seek(0)` 可回到开头。
`File::Create` 截断后从 0 开始写；`File::ReadDir` 只返回直接子项，条目顺序固定为文件名字典序。
`File` 属于 hosted 能力，不在 `core`，也不由 GC 自动管理句柄。

第一版 native 后端在 `std-posix/native/file.rs`，以 Rust `staticlib` 导出 C ABI。
构建并链接：

```bash
bash tools/build_std_native.sh
./build/mylc src/main.myl -I std/src -I std-posix/native \
  --link build/std-posix/native/libmylis_file.a -o build/app
```

`-I` 现在同时作为 Mylis 模块搜索根和 C 头文件搜索路径；`@header("mylis_file.h")`
从 `std-posix/native/` 找到。非嵌入 native 不随源码包/`.mylib` 自动传播，最终链接者必须显式提供
`--link`，和包约定一致。当前只在 Linux/POSIX 上验证；Windows MSVC/GNU 的静态库打包与真实链接仍待补。

### 4.5.6 标准库：TcpListener / TcpStream（hosted）

`std/src/TcpListener.myl` 与 `std/src/TcpStream.myl` 提供第一版阻塞/非阻塞 TCP：

```myl
import { TcpListener } from "TcpListener.myl";
import { TcpStream } from "TcpStream.myl";
import { IoError } from "IoError.myl";
import { Str } from "core/Str";
import { fmt_i64 } from "core/Fmt";

fn main() -> i32 {
    Result<TcpListener, IoError> bound = TcpListener::Bind("127.0.0.1:0");
    match bound {
        Ok(listener) => {
            i64 port = listener.localPort();
            string addr = Str::Concat("127.0.0.1:", fmt_i64(port));
            Result<TcpStream, IoError> client = TcpStream::Connect(addr);
            /* 先 connect 再 accept：连接会进入监听队列 */
        }
        Err(e) => { /* e.kind / e.code */ }
    }
    return 0;
}
```

API：

- `TcpListener::Bind(address) -> Result<TcpListener, IoError>`
- `TcpListener::localPort() -> i64`，失败返回负值
- `TcpListener::accept() -> Result<TcpStream, IoError>`
- `TcpListener::setNonblocking(bool) -> Result<i64, IoError>`
- `TcpStream::Connect(address) -> Result<TcpStream, IoError>`
- `TcpStream::read(maxBytes) -> Result<u8[], IoError>`
- `TcpStream::writeAllBytes(u8[])` / `TcpStream::writeAllText(string) -> Result<i64, IoError>`
- `TcpStream::setNonblocking(bool)` / `TcpStream::setTimeout(ms) -> Result<i64, IoError>`
- `TcpListener::close()` / `TcpStream::close()`：显式关闭

第一版不做 `async/await`；`TcpListener/TcpStream` 自身没有事件循环，阻塞 `accept` / `connect` / `read` 会占住当前线程。需要就绪分发时再接 `EventLoop`（见 4.5.8）。
非阻塞模式下没有就绪连接/数据时返回 `Err(IoErrorKind::WouldBlock)`，不是致命错误。
地址先使用 `"host:port"` 字符串。

TCP native 后端是 `std-posix/native/net.rs`（Rust staticlib，C ABI），构建后与 File 一起链接：

```bash
bash tools/build_std_native.sh
./build/mylc src/main.myl -I std/src -I std-posix/native \
  --link build/std-posix/native/libmylis_file.a \
  --link build/std-posix/native/libmylis_net.a -o build/app
```

当前同样只在 Linux/POSIX 上验证；Windows 的 Winsock ABI 和静态库打包待补。

### 4.5.7 标准库：UdpSocket（hosted）

`std/src/UdpSocket.myl` 提供第一版阻塞 UDP：

```myl
class UdpSocket {

    pub fn localPort() -> i64;
    pub fn sendTo(string address, u8[] data) -> Result<i64, IoError>;
```

### 4.5.8 标准库：EventLoop（hosted，POSIX 第一版）

`std/src/EventLoop.myl` 提供单线程事件循环；回调使用 `IoHandler` interface，不使用闭包：

```myl
interface IoHandler {
    fn onAccept(TcpListener listener) -> void;
    fn onReadable(TcpStream stream) -> void;
    fn onWritable(TcpStream stream) -> void;
    fn onError(TcpStream stream, IoError error) -> void;
    fn onListenerError(TcpListener listener, IoError error) -> void;
    fn onUdpReadable(UdpSocket socket) -> void;
}
```

```myl
class EventLoop {
    pub fn add(TcpStream stream, IoHandler handler) -> void;
    pub fn addListener(TcpListener listener, IoHandler handler) -> void;
    pub fn addUdp(UdpSocket socket, IoHandler handler) -> void;
    pub fn setWriteInterest(TcpStream stream, bool enabled) -> void;
    pub fn remove(TcpStream stream) -> void;
    pub fn removeListener(TcpListener listener) -> void;
    pub fn removeUdp(UdpSocket socket) -> void;
    pub fn run() -> void;
    pub fn stop() -> void;
    pub fn close() -> void;
}
```

- 注册时会把 socket 设为非阻塞。
- Linux 使用 `epoll`，其他 POSIX 使用 `poll` 后备；`run()` 在主线程分发 handler，Rust 后端不执行 Mylis 回调。
- 默认只关注读就绪；显式 `setWriteInterest(stream, true)` 后才触发 `onWritable`，避免 socket 一直可写导致忙循环。
- UDP 通过 `addUdp` 注册，读就绪触发 `onUdpReadable`。
- 监听器错误通过 `onListenerError` 回调，与 `onError` 分开。
- `remove` / `removeListener` 用于从循环中注销；`close` 关闭事件后端。
- Windows 目前返回 `ENOSYS`。
- 需要同时链接 `libmylis_event.a`：

```bash
./build/mylc src/main.myl -I std/src -I std-posix/native \
  --link build/std-posix/native/libmylis_net.a \
  --link build/std-posix/native/libmylis_event.a -o build/app
```

### 4.5.9 标准库：Path（纯 Mylis）

`std/src/Path.myl` 提供不访问文件系统的路径工具：

```myl
class Path {
    pub static fn Join(string left, string right) -> string;
    pub static fn BaseName(string value) -> string;
    pub static fn DirName(string value) -> string;
    pub static fn Extension(string value) -> string;
    pub static fn Stem(string value) -> string;
```

- 同时接受 `/` 与 `\`

- `Extension` 不把 `.bashrc` 识别为扩展名

### 4.5.10 自动选择 std 平台后端：`--std`

`mylc` 和 `mylc build/run` 支持 `--std`；入口源码出现 `"std/..."` 导入，或工程清单直接/经本地路径间接依赖 `std` 时，也会自动启用：

```bash
mylc --std src/main.myl -o build/app
mylc build --std
```

自动触发看两类信号：入口源码里的 `"std/..."`，以及清单里的 `std = { ... }` 依赖（会沿本地 `path` 依赖递归检查，最多 8 层）。它不检查 registry/git/mylib 远程依赖；直接写 `import ... from "Path.myl"` 并用 `-I std/src` 的工程不会触发，需要显式 `--std`。它会：

- 找到 `std` 包根（优先 `MYLIS_STD_ROOT`，否则从 cwd 向上找 `std/mylis.toml`，最后尝试编译器旁的工程根）
- 加入 `std/src`
- 加入工程根，供 std 里的 `core/...` 解析
- 在 Linux/POSIX 上加入 `std-posix/native` 头文件路径
- 如果 `build/std-posix/native/libmylis_file.a`、`libmylis_io.a`、`libmylis_time.a`、`libmylis_net.a`、`libmylis_event.a`、`libmylis_process.a` 存在，自动加入链接

典型触发形式是包依赖：

```myl
import { File } from "std/File";
```

此时 `std` 源码由包系统解析；`--std` 负责补平台 native 路径和链接。

`--std` 不改变包的嵌入规则：native 仍是非嵌入的，最终链接者必须能访问这些 `.a`。
Windows 侧车尚未提供，`--std` 在 Windows 上只加源码/头文件，不会自动链接 File/TCP/UDP 后端。

### 4.5.11 迭代器与 PriorityQueue

`std/src/Iterator.myl` 定义显式迭代器协议，不引入 `for-in` 或闭包：

```myl
import { Iterator } from "Iterator.myl";
import { Vec } from "Vec.myl";
import { VecIter } from "VecIter.myl";

Vec<i64> values = new Vec<i64>();
values.push(1);
Iterator<i64> it = new VecIter<i64>(values);
while (true) {
    match (it.next()) {
        Some(v) => { println_i64(v); }
        None => { break; }
    }
}
```

容器迭代器：

- `VecIter<T>`：`Vec<T>`，构造 `new VecIter<T>(vec)`；`iter(vec)` 自由函数
- `MapIter<K: Eq, V>`：`Map<K,V>`，元素是 `MapEntry<K,V>`；`iter_map(map)`
- `SetIter<T: Eq>`：`Set<T>`；`iter_set(set)`
- `QueueIter<T>`：`Queue<T>`；`iter_queue(queue)`
- `DequeIter<T>`：构造时快照 `Deque<T>`；`iter_deque(deque)`
- `HashMapIter<K: Hash + Eq, V>`：快照 `HashMap<K,V>` 的键值对；`iter_hash_map(map)`
- `BTreeMapIter<K: Ord, V>`：按 key 升序返回键值对；`iter_btree_map(map)`
- `BTreeSetIter<T: Ord>`：按元素升序返回；`iter_btree_set(set)`
- `RangeIter`：`Iter::Range(start, end)` / `Iter::RangeStep(start, end, step)`

`MapEntry` 用 `getKey()` / `getValue()` 取字段，避免跨泛型实例直接访问字段。
所有迭代器都只提供 `next()`，没有 `map/filter` 惰性适配器；这需要语言层闭包或函数值支持。

`std/src/PriorityQueue.myl` 提供基于 `Vec<T>` 的大顶堆，要求 `T: Ord`：

```myl
PriorityQueue<i64> q = new PriorityQueue<i64>();
q.push(3);
q.push(7);
match (q.pop()) {
    Some(v) => { println_i64(v); }
    None => { }
}
```

API：`push`、`pop() -> Option<T>`、`peek() -> Option<T>`、`len()`、`isEmpty()`、`clear()`。
`push/pop` 为 O(log n)；不提供并发安全保证。

### 4.5.12 HashMap / BTreeMap / BTreeSet

`std/src/HashMap.myl` 是开放寻址哈希表，要求 `K: Hash + Eq`：

```myl
import { HashMap } from "HashMap.myl";

HashMap<string, i64> map = new HashMap<string, i64>();
map.set("alpha", 1);
map.insert("beta", 2);
Option<i64> value = map.get("beta");
println_i64(map.getOr("beta", -1));
```

API：`set`、`insert`（返回是否新增）、`get`、`getOr`、`containsKey`、`remove`、`keys`、`values`、`len`、`isEmpty`、`clear`。
线性探测 + 墓碑删除，负载因子超过 3/4 时扩容并重建；遍历顺序不保证。
自定义 class 要作为 key，需要同时实现 `Eq`（`core/Eq`）与 `Hash`（`core/Hash`，`hash() -> u64`），并保证相等对象返回相同哈希。

`std/src/BTreeMap.myl` 是最小度数 2 的 B 树（单节点最多 3 个键、4 个孩子），`BTreeSet.myl` 包装 `BTreeMap<T, bool>`：

```myl
BTreeMap<string, i64> ordered = new BTreeMap<string, i64>();
ordered.set("gamma", 3);
ordered.set("alpha", 1);
Vec<string> keys = ordered.keys();   // alpha, gamma
Option<string> first = ordered.firstKey();
```

`BTreeMap`：`set/insert/get/getOr/containsKey/remove/keys/values/firstKey/lastKey/len/isEmpty/clear`。
`BTreeSet`：`add/remove/contains/first/last/toVec/len/isEmpty/clear`。
查找、插入、删除均为 O(log n)（插入用自顶向下分裂，删除用借位/合并）；`keys()/values()/toVec()` 按升序返回。
容器不保证并发安全；多线程共享同一容器需要调用方自行加锁。

### 4.5.13 CSV / Base64

`std/src/Csv.myl` 提供 RFC 4180 风格解析和序列化：

```myl
Result<Vec<Vec<string>>, string> rows = Csv::Parse("a,b\n1,2\n");
Vec<Vec<string>> table = new Vec<Vec<string>>();
Vec<string> row = new Vec<string>();
row.push("x");
row.push("y,z");
table.push(row);
string encoded = Csv::Stringify(table);
```

解析支持双引号字段、字段内逗号/换行、`""` 转义、CRLF/LF；空输入返回空表。
非 ASCII 文本按 UTF-8 字节切片，不会把字节下标误当作字符下标。
引号未闭合、引号后多余字符、非法分隔符、未加引号字段中的 `"` 都会返回带字节位置的 `Err`。
`Stringify` 会对空字段以及含逗号、引号、CR/LF 或首尾空白的字段加引号，内部引号写成 `""`，行间用 `\n`；单空字段往返为 `""`。

`std/src/Base64.myl` 使用 RFC 4648 标准字母表：

```myl
string encoded = Base64::Encode("hello, 世界");
Result<string, string> decoded = Base64::Decode(encoded);
```

`EncodeBytes(u8[])` / `DecodeBytes(string)` 直接处理任意二进制；`Encode(string)` / `Decode(string)` 是 UTF-8 文本便捷入口。
编码固定补 `=`；解码接受标准字母表、`=` 填充和 ASCII 空白，
对长度、非法字符、填充位置、超过两个 `=` 以及非规范的尾部位做严格检查。

### 4.5.14 文本解析：Text

`std/src/Text.myl` 在原有 `Split` / `Join` / `Lines` / `ParseI64` / `ParseU64` 基础上增加：

```myl
Option<i32> n = Text::ParseI32("2147483647");
Option<f64> f = Text::ParseF64(" -12.5e2 ");
Vec<string> words = Text::SplitWhitespace(" a\tb\nc ");
```

- `ParseI32`：先按 `ParseI64` 解析，再检查 32 位范围
- `ParseF64`：支持符号、小数、指数；拒绝 NaN/Inf 字面量和尾部垃圾
- `SplitWhitespace`：按 ASCII 空白（空格、tab、换行、CR、VT、FF）切分并丢弃空段

### 4.5.15 JSON

`std/src/Json.myl` 提供对象、数组、字符串、整数、浮点、布尔与 null 的严格解析和紧凑序列化：

```myl
import { Json } from "Json.myl";

Result<Json, string> parsed = Json::Parse("{{\"name\":\"mylis\"}}");
match parsed {
```

构造与读取：

- `Json::Null()`、`Json::Bool`、`Json::Int`、`Json::Float`、`Json::Str`、`Json::Array`、`Json::Object`
- `isNull`、`asBool`、`asInt`、`asFloat`、`asString`、`asArray`、`asObject`
- `at(index)` / `get(key)` / `len()`

### 4.5.16 Time / Random / Log

`std/src/Time.myl`（hosted，需要 `libmylis_time.a`）：

```myl

Time::SleepMillis(10);
```

- `NowMillis()`：Unix 纪元毫秒
- `NowNanos()`：Unix 纪元纳秒，i64 可表示到约 2262 年
- `MonotonicMillis()`：单调毫秒，适合测耗时
- `NowSeconds()`：Unix 纪元秒，f64
- `SleepMillis(ms)`：当前线程睡眠

`std/src/Random.myl` 是纯 Mylis 的 xorshift64*，非密码学：

```myl
Random r = new Random(12345);

```

API：`nextU32`、`nextI32`、`nextU64`、`nextF64`、`range(min, maxExclusive)`、`nextBool`、`reseed(seed)`。

`std/src/Log.myl` 提供 `Log::Debug/Info/Warn/Error(string)`，输出到标准输出并加 `[级别] ` 前缀。

并发边界：当前 runtime 和语言语义是单线程，不提供 `Thread` / `Mutex` / `Atomic` / `Channel`；
`EventLoop` 仍是单线程回调。要支持真正的语言级线程，需要先改 GC、根集合和安全点模型，而不是只加几个 std 类。
需要并行时用下面的 `Worker`：每个 worker 是独立进程、独立 runtime/GC 堆，只通过管道消息通信，不需要改 runtime。

### 4.5.17 Process（hosted，shell 进程）

`std/src/Process.myl` 对齐 Lua 的 `os.execute` / `io.popen` 思路：`Run` 是同步命令，`Spawn` 返回轻量句柄，不做异步回调，也不共享 Mylis 堆。

```myl
import { Process } from "Process.myl";
import { ProcessOutput } from "ProcessOutput.myl";
import { IoError } from "IoError.myl";

Result<ProcessOutput, IoError> result = Process::Run("printf 'hello'");
match (result) {
    Ok(output) => {
        println_i64(output.exitCode());
        println(output.stdout());
        println(output.stderr());
        println_bool(output.success());
    }
    Err(error) => { println(error.message); }
}
```

`Process::Run` 会同步等待结束，捕获 stdout/stderr，返回 `exitCode`、`signal` 和 `success()`。

需要 PID 或异步生命周期时用 `Spawn`：

```myl
import { Process } from "Process.myl";
import { ProcessStatus } from "ProcessStatus.myl";
import { IoError } from "IoError.myl";

Result<Process, IoError> spawned = Process::Spawn("sleep 5");
match (spawned) {
    Ok(proc) => {
        println_i64(proc.pid());
        proc.kill();
        Result<ProcessStatus, IoError> status = proc.wait();
        match (status) {
            Ok(done) => { println_i64(done.signal()); }
            Err(error) => { println(error.message); }
        }
        proc.close();
    }
    Err(error) => { println(error.message); }
}
```

需要单向管道或原始字节时用 `Popen`：

```myl
import { Process } from "Process.myl";
import { ProcessPipe } from "ProcessPipe.myl";
import { IoError } from "IoError.myl";

Result<ProcessPipe, IoError> opened = Process::Popen("printf 'A\\000B'", "r");
match (opened) {
    Ok(pipe) => {
        Result<u8[], IoError> bytes = pipe.readAll();
        match (bytes) {
            Ok(data) => { println_i64(data.len() as i64); }
            Err(error) => { println(error.message); }
        }
        pipe.close();
    }
    Err(error) => { println(error.message); }
}
```

`mode` 为 `"r"` 时读子进程 stdout，`"w"` 时写子进程 stdin；`readAll()` 返回 `u8[]`，保留 NUL 和任意二进制字节；`write(u8[])` 返回写入字节数；`close()` 关闭管道、等待子进程并返回 `ProcessStatus`。

双向管道用 `Process::Popen2`：

```myl
import { Process } from "Process.myl";
import { ProcessPipe } from "ProcessPipe.myl";
import { IoError } from "IoError.myl";
import { Str } from "core/Str";

Result<ProcessPipe, IoError> opened = Process::Popen2("cat");
match (opened) {
    Ok(chan) => {
        chan.write(Str::Bytes("hello"));
        chan.closeInput();          // 先通知子进程 stdin EOF
        Result<u8[], IoError> data = chan.readAll();
        match (data) { Ok(bytes) => { println_i64(bytes.len() as i64); } Err(error) => { println(error.message); } }
        chan.close();
    }
    Err(error) => { println(error.message); }
}
```

`Popen2` 同时打开 stdin/stdout；写入后必须 `closeInput()` 再 `readAll()`，否则读会等待子进程 EOF。子进程 stderr 继承父进程；不做非阻塞/select 多路复用。

- `Spawn` 立即返回，子进程继承父进程的 stdin/stdout/stderr；
- `pid()`、`kill()`、`wait()`、`close()`；`wait()` 成功后句柄失效，`close()` 只释放已 wait 过的句柄；
- 子进程仍在运行时 `close()` 返回 `EBUSY`（errno 16），必须先 `wait()` 或 `kill()` 后再 `wait()`；
- POSIX 下用 `/bin/sh -c`，Windows 下用 `cmd /C`；
- 不提供异步退出回调；需要回调时必须另做事件队列，不能从 native 线程直接进入 Mylis；
- 子进程有独立地址空间，不共享 Mylis 堆；
- 需要显式链接 `libmylis_process.a`，`--std` 会自动加入；
- `Run` 输出按文本处理并复制为 Mylis `string`；`Popen`/`Popen2` 读取/写入原始 `u8[]`，保留 NUL 字节；
- `ProcessPipe::readLine()` 逐行读取；`readLineTimeout(ms)` 超时返回 `IoError(110)`；`readLine` 之后的 `readAll` 只读取剩余字节；
- `ProcessPipe::terminate()` 强制 kill 子进程并 wait；`close()` 仍是正常关闭，可能等待子进程自己退出。

#### Worker（进程隔离的消息层）

`std/src/Worker.myl` 用 `Popen2` 把一个独立 Mylis 进程包装成消息对端：每个 worker 有自己的地址空间、自己的 runtime 和 GC 堆，双方只通过 stdin/stdout 交换字节，不共享 class、闭包、容器引用或 GC 对象。它不引入语言级 `Thread`，也不需要改 runtime/GC；这就是 Lua 里 `io.popen` 加消息协议的做法。

协议是**一行一条消息**：`send` 自动追加 `\n`，`recv` 读取一行并去掉行尾换行。消息内部不能含裸换行；结构化消息先用 `Json::Stringify` 生成 JSON 字符串，worker 侧用 `Json::Parse` 还原。

```myl
import { Worker } from "Worker.myl";
import { Json } from "Json.myl";
import { Map } from "Map.myl";
import { IoError } from "IoError.myl";
import { println } from "Io.myl";

Result<Worker, IoError> spawned = Worker::Spawn("./build/worker");
match (spawned) {
    Ok(worker) => {
        Map<string, Json> args = new Map<string, Json>();
        args.set("op", Json::Str("upper"));
        args.set("text", Json::Str("hello"));
        Result<string, IoError> reply = worker.callTimeout(Json::Stringify(Json::Object(args)), 1000);
        match (reply) {
            Ok(text) => { println(text); }
            Err(error) => { println(error.message); }
        }
        worker.shutdown();
    }
    Err(error) => { println(error.message); }
}
```

worker 侧用 `WorkerServer`，不再手写 stdin 循环；handler 只负责把一行请求变成一行响应：

```myl
import { WorkerServer } from "WorkerServer.myl";
import { WorkerHandler } from "WorkerHandler.myl";
import { Json } from "Json.myl";

class UpperHandler {
    pub fn handle(string request) -> string {
        // 解析 request，处理，然后返回单行 JSON
        return Json::Stringify(Json::Str("ok"));
    }
}

fn main() -> i32 {
    WorkerServer::Run(new UpperHandler());
    return 0;
}
```

- `Worker::Spawn(command)` 启动 `Popen2` 子进程并立即返回；`pid()` 返回子进程 PID；
- `send(message)` 返回写入字节数（包含追加的 `\n`）；`recv()` 在子进程关闭 stdout 后返回 `Ok(None)`；
- `recvTimeout(ms)` / `callTimeout(message, ms)` 带阻塞读超时；超时返回 `Err(IoError(110))`；
- `call(message)` 等价于 `send` 后 `recv`；遇到 EOF 返回 `Err(IoError(9))`；
- `close()` 关闭 stdin/stdout 并等待子进程，返回 `ProcessStatus`；
- `shutdown()` 发送保留控制行 `__shutdown__` 后关闭；`WorkerServer` 收到后退出，按行读 stdin 的普通 worker 也会因 EOF 退出；
- `terminate()` 直接 kill 并 wait，不等待 worker 自己退出；适合 `callTimeout` 后清理不响应的 worker；
- `WorkerServer` + `WorkerHandler` 提供 worker 侧标准入口；handler 的返回值必须是一行，不能含裸换行；
- 没有共享内存、共享锁或跨进程 GC 根；消息是深拷贝后的字节；
- worker 的 stdout 只用于协议行，日志请写 stderr，否则会污染响应流；
- 消息内容里不能有裸换行；结构化消息用 `Json::Stringify`，不要手工拼 JSON 字符串；
- 没有内建取消；超时只是读超时，不会杀掉 worker，超时后可以继续 `recv` 或 `close`；
- 子进程 stderr 继承父进程；不做非阻塞/select 多路复用；
- 底层依赖 `ProcessPipe::readLine()` / `readLineTimeout()`：读到一行返回 `Ok(Some(line))`，EOF 返回 `Ok(None)`，错误返回 `Err(IoError)`；`readLine` 之后的 `readAll` 只读取剩余字节。

#### WorkerPool（固定进程池）

`WorkerPool` 用固定数量的独立 worker 做同步 fan-out/fan-in。任务仍是一行一条消息，结果按**提交顺序**返回；worker 之间不共享堆，也不引入线程。

```myl
import { WorkerPool } from "WorkerPool.myl";
import { Vec } from "Vec.myl";
import { IoError } from "IoError.myl";
import { println } from "Io.myl";

Result<WorkerPool, IoError> spawned = WorkerPool::Spawn("./build/worker", 4);
match (spawned) {
    Ok(pool) => {
        Vec<string> tasks = new Vec<string>();
        tasks.push("a");
        tasks.push("b");
        tasks.push("c");
        Result<Vec<string>, IoError> results = pool.callAll(tasks);
        match (results) {
            Ok(values) => {
                i64 i = 0;
                while (i < values.len) {
                    println(values.get(i));
                    i = i + 1;
                }
            }
            Err(error) => { println(error.message); }
        }
        pool.close();
    }
    Err(error) => { println(error.message); }
}
```

- `Spawn(command, count)`：启动 count 个 worker；任一启动失败会 terminate 已启动的 worker；
- `callAll(tasks)`：全有或全无；任一任务失败返回该任务的 `IoError`，对应 worker 已经被重启；
- `callAllTimeout(tasks, ms)`：同上，但每条响应最多等待 ms 毫秒，超时错误为 `IoError(110)`；
- `callAllResults(tasks, ms)`：每个任务单独返回 `WorkerTaskResult`，一个 worker 超时/退出只重启该槽位，其他任务继续；返回顺序仍是 `tasks` 的顺序；
- `WorkerTaskResult` 有 `ok`、`value`、`code` 字段：成功时 `ok = true`、`code = 0`，失败时 `ok = false`、`code` 为错误码；
- `close()`：逐个正常关闭，返回关闭的 worker 数；任一失败会 terminate 整池并返回错误；
- `terminate()`：强制清理整池，忽略单个 worker 的清理错误，返回尝试清理的 worker 数；
- 任务数量可以大于 worker 数量；不提供动态扩容、优先级或异步回调；需要这些能力时在协议层或上层调度里做。

## 4.6 泛型枚举与 bound

```myl
interface Show {
    fn show() -> string;
}

enum Maybe<T> {
    Nothing,
    Just(T),
}

fn pick<T: Show>(T value) -> T { return value; }

Maybe<i64> m = Maybe<i64>::Just(7);
match m {
    Maybe::Just(x) => { println_i64(x); }
    Maybe::Nothing => { println_i64(0); }
}
```

`T: Show` 要求实参类型具备 `Show` 接口要求的同名方法；实例化时检查，不满足报 `MYL102`。
类型实参可显式写 `<...>`，也可在简单场景下按期望类型和字面量参数推断；bound 只能是 interface。

## 5. 生成库并从 C 调用

### 5.1 生成静态库

```bash
mylc --static libmath.myl -o libmathlib
```

```text
libmathlib.a
libmathlib.h
```

头文件只导出带 `@export` 的顶层函数，并包含 `#include "mylrt.h"`，同时声明：

```c
void <stem>_init(void);
```

### 5.2 生成动态库

```bash
mylc --shared libmath.myl -o libmathlib
```

Linux 得到 `.so`，Windows 得到 `.dll`。Windows 下默认把运行时链接进 DLL；Linux 默认不把运行时链进 `.so`，需要时加 `--embed-runtime`。

导出函数参数仍限制在 C 能稳定表达的基础类型。返回值支持 `Option` / `Result` 的常见小聚合：8 字节 `Option`（如 `Option<i32>`）按 C 的打包返回约定生成，16 字节 `Option` / `Result`（如 `Option<string>`、`Result<i32,string>`）按 C 的寄存器返回约定生成；其他尺寸或作为参数的 `Option` / `Result` 仍会被拒绝，避免静默 ABI 不一致。上述小聚合返回约定按 x86-64 SysV（Linux/macOS 的 clang/gcc）验证；MSVC 的聚合 ABI 不同，暂不套用。

### 5.3 C 客户端

```c
#include "libmathlib.h"

int main(void) {
    libmathlib_init();
    /* 调用 @export 的函数 */
    return 0;
}
```

```bash
cc client.c libmathlib.a \

```

在 **运行 `mylc`** 时设置：

```bash
MYLIS_GC=own    bin/mylc app.myl -o app    # 默认
MYLIS_GC=simple bin/mylc app.myl -o app    # 不回收，调试用
MYLIS_GC=boehm  bin/mylc app.myl -o app    # 需要 Boehm 库
```

`MYLIS_GC_THRESHOLD` 可以设置自研 GC 的自动回收阈值（字节）。设为 `0` 关闭自动回收。

`MYLIS_GC_PRECISE=1` 打开自研 GC 的精确根模式：GC 只扫描显式注册的根区间，不再保守扫描线程栈。该模式对 **LLVM 后端**和 **MIR-C 后端**（`--backend mir`）生成的程序可用：两者都会在函数入口创建帧根表，并在每个 safepoint 填入该点当前活跃的根快照、在返回前注销帧；静态引用字段通过独立的静态根表注册。AST-C 回退路径不保证帧根完整，不要在该路径打开此变量。默认不设置，保持保守扫描。

### 6.3 运行时库位置

`mylc` 按以下顺序寻找安装根：

1. `MYLIS_ROOT`
2. 编译时写入的默认根
3. 可执行文件自身目录
4. 可执行文件父目录
5. 当前目录

因此 `bin/` 整体拷贝后可直接使用；只拷贝 `mylc` 时需要设置 `MYLIS_ROOT`。

## 7. 环境变量速查

| 变量 | 作用 |
|---|---|
| `MYLIS_ROOT` | 安装根，包含 `myrt/mylrt.h` |
| `MYLIS_PATH` | 追加模块搜索路径 |
| `MYLIS_TOOLCHAINS` | 追加工具链规格目录 |

## 8. 常见问题

### `无法启动编译器 clang`

默认 LLVM 后端需要 LLVM 15+ 的 `clang`。安装后确认：

```bash
clang --version
```

或者显式回退：

```bash
mylc --backend mir app.myl -o app
```

### `undefined reference to myrt_gc_backend_*`

通常是 `build/libmylrt.a` 和 GC 库不是同一套，或者只拷贝了运行时没拷贝 GC。重新执行：

```bash
make all
```

并确认 `bin/build/` 下同时有 `libmylrt.a` 和 `libmylgc.a`（Windows 为 `.lib`）。

### `未找到工具链规格`

设置 `MYLIS_FAMILY=gcc` / `msvc`，或把自定义 `*.toml` 放到 `~/.mylis/toolchains/`、工程 `.mylis/toolchains/`。

### 模块找不到

检查：

1. `mylis.toml` 的 `[build] paths`
2. 命令行 `-I`
3. `MYLIS_PATH`

### Windows 上 MSVC 找不到

必须在 VS 开发者命令提示符里运行；`cl.exe`、`lib.exe` 必须在 PATH。
