# 网络与事件

本章覆盖通用 fd 事件循环、TCP/UDP/Unix socket、缓冲 TCP 流和各协议 handler。`EventLoop` 只认识 fd 与 `FdHandler`，不认识 TCP/UDP/Unix；`TcpEventLoop`、`UdpEventLoop`、`UnixEventLoop` 负责把协议对象适配成 fd 回调。socket 默认是阻塞语义，只有显式 `setNonblocking(true)` 后才进入非阻塞模式；事件循环回调在主线程执行。

## `EventLoop.myl` — EventLoop

**文件职责**：单线程通用 fd 事件循环：事件后端等待 fd 就绪 -> Mylis 主线程分发 FdHandler。 Linux 使用 epoll，其他 POSIX 使用 poll 后备，Windows 使用 Winsock WSAPoll；Rust 后端不执行 Mylis 回调。 不直接依赖 TCP/UDP/File；协议适配器和文件完成泵通过类组合接入。

### EventLoop

**类型**：`pub class EventLoop`（class）

单线程通用 fd 事件循环：事件后端等待 fd 就绪 -> Mylis 主线程分发 FdHandler。

**公开方法**：

| 签名 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `init() -> void` | 无 | `void` | 构造并初始化对象；参数写入实例状态。除类说明特别指出外，不在此处分配 OS 资源。 |
| `add(i64 fd, FdHandler handler) -> void` | i64 fd, FdHandler handler | `void` | 注册 fd 与 handler；重复 fd 的行为由实现约定。 |
| `setWriteInterest(i64 fd, bool enabled) -> void` | i64 fd, bool enabled | `void` | 开启/关闭 fd 的写就绪监听；需要该 fd 已注册。 |
| `remove(i64 fd) -> void` | i64 fd | `void` | 注销并移除对应 fd/监听器/流；不关闭底层句柄，除非类说明。 |
| `addPump(EventPump pump) -> void` | EventPump pump | `void` | 挂入泵；EventLoop 会调用其 hasPending/nextTimeoutMillis/pump/shutdown。 |
| `run() -> void` | 无 | `void` | 分发 fd 事件和泵任务，直到 stop/close 或没有 fd/泵。 |
| `stop() -> void` | 无 | `void` | 请求事件循环在本次分发结束后退出。 |
| `close() -> void` | 无 | `void` | 停止循环、shutdown 所有泵并关闭事件后端句柄。 |

| --- | --- | --- | --- |
